# Inimerse 内糖与外糖规范（V0.4 草案）

## 定义

**内糖**是语言核心直接支持的简洁表达：可以由 lexer/parser/compiler 直接解释或编译，不依赖脱糖脚本，语义和性能接近核心形式。

**外糖**是翻译层支持的表达：由 `desugar_mod` 或外部转换器改写为核心语法，主要服务于其他范式、迁移、别名和用户自定义，不扩大核心 AST/VM 语义。

## 当前分类

### 内糖（已由核心前端直接支持）

- 分号容忍和语句结束推断
- `..`/区间字面量及集合区间表达式
- `++`/`--`（lexer/parser/compiler 直接生成加减字节码）
- f-string 插值 `$"..."`（解析期生成字符串拼接表达式）
- 尾逗号
- `?.`、`??`（仅在对应核心语法完成后列入；当前仍是设计项）

### 内糖（V0.4 已确定）

以下函数式表达属于语言核心，而不是外部翻译别名；实现后由 lexer/parser/compiler 直接处理，不要求运行 `--desugar`：

- `|>` 管道（`value |> fn(a)` 由核心前端直接降为 `fn(value, a)`）
- `?` Result 错误传播（顶层降低为 `unwrap(expr)`；函数级 Err 返回会先执行活跃 `finally`；cleanup 中 `break/continue` 在传播路径上被拒绝）
- lambda：`x -> expr`
- `>>` 函数组合
- 集合推导：`{ f(x) | x in S, cond }`（当前实现为筛选式 `{ x in S | cond }`）

这些项目已经确定为内糖，并已由核心 parser/compiler 路径接入；闭包生命周期和复杂部分应用仍按 V0.4 状态矩阵持续完善。

### 外糖（当前由脱糖层转换）

- `fn` → `func`
- `print` → `say`
- `&&` → `and`、`||` → `or`
- `//` → `#`
- `unless ... {}` → `if !(...) {}`
- `say@target expr` → `say_target("target", expr)`
- `eidos` / `ed` → 工厂函数、字典实例和闭包方法（由 `tools/eidos_desugar.py` 转换）
- 用户自定义别名和迁移器产生的其他语言习惯表达

`inimerse --desugar` 是外糖的显式转换工具；外糖不应要求 VM 增加专用 opcode。

## V0.4 规则

1. 新增内糖必须有直接 parser/compiler 测试和解释器回归测试。
2. 新增外糖必须有脱糖前后等价性测试，并保证字符串、注释和嵌套结构不被误改写。
3. `Result` 的 `?`、管道 `|>`、lambda、函数组合和集合推导确定为内糖；这些项目均已有核心 parser/compiler 路径，复杂部分应用和表达式级 `case` 仍属于后续扩展。
4. `eidos`、`ed` 等对象/关键字别名属于外糖；当前只冻结可执行子集，不把它们升级为核心 AST/VM 对象模型。
5. 集合到类型/对象的映射由翻译器负责，核心语言只保留可验证的基础集合和运行时值。

## Eidos V0.4 可执行子集

`eidos Name { ... }` 和 `ed Name { ... }` 会被转换为一个同名工厂函数。字段使用
`name = expression` 声明，构造时按字段声明顺序接收参数；参数为 `nil` 时使用字段默认值。
方法使用 `method(args) { ... }` 或单行形式 `method(args) -> expression` 声明，
并以闭包写入实例字典。实例方法通过 `object["method"](...)` 调用，方法体可直接读写
实例字段。

当前支持：简单字段默认值、无参/有参方法、单行方法、字段引用、`init` 方法自动调用、
单继承、方法覆盖和有限的 `super.method(...)` 调用。父类必须先声明；子类字段会覆盖同名
父类字段，父类方法在子类实例上读取最终字段值。
当前不支持：mixin、可见性声明、sealed/frozen/invariant、热修改，以及自动无括号方法调用
语法。mixin 输入会由脱糖器明确拒绝。

## 当前状态结论

仓库此前没有这份正式分类；本文件将其冻结为 V0.4 草案。现有实现中，`fn`、`print`、`&&/||`、`//`、`unless` 和 `say@target` 按外糖处理；区间、分号容忍、`++/--`、f-string 和尾逗号按内糖处理。
