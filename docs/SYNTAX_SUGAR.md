# Inimerse 内糖与外糖规范（V0.4 草案）

## 定义

**内糖**是语言核心直接支持的简洁表达：可以由 lexer/parser/compiler 直接解释或编译，不依赖脱糖脚本，语义和性能接近核心形式。

**外糖**是翻译层支持的表达：由 `desugar_mod` 或外部转换器改写为核心语法，主要服务于其他范式、迁移、别名和用户自定义，不扩大核心 AST/VM 语义。

## 当前分类

### 内糖（已由核心前端直接支持）

- 分号容忍和语句结束推断
- `..`/区间字面量及集合区间表达式
- `++`/`--`（lexer/parser/compiler 直接生成加减字节码）
- f-string 插值 `$"..."`（解析期生成字符串拼接表达式）
- 尾逗号
- `?.`、`??`（仅在对应核心语法完成后列入；当前仍是设计项）

### 内糖（V0.4 已确定，部分待实现）

以下函数式表达属于语言核心，而不是外部翻译别名；实现后由 lexer/parser/compiler 直接处理，不要求运行 `--desugar`：

- `|>` 管道（`value |> fn(a)` 由核心前端直接降为 `fn(value, a)`）
- `?` Result 错误传播（当前核心实现为 `unwrap(expr)` postfix；函数级 Err 返回传播后续增强）
- lambda：`x -> expr`
- `>>` 函数组合
- 集合推导：`{ f(x) | x in S, cond }`（当前实现为筛选式 `{ x in S | cond }`）

这些项目已经确定为内糖；其中管道、Result `?` 和集合推导已有核心 parser/compiler 路径，lambda 与函数组合会在接入前保持“语法未支持”状态，但不会改列为外糖。

### 外糖（当前由脱糖层转换）

- `fn` → `func`
- `print` → `say`
- `&&` → `and`、`||` → `or`
- `//` → `#`
- `unless ... {}` → `if !(...) {}`
- `say@target expr` → `say_target("target", expr)`
- `eidos` / `ed` → `record`（由 `tools/eidos_desugar.py` 转换）
- 用户自定义别名和迁移器产生的其他语言习惯表达
- 简单函数名组合 `f >> g`（脱糖为 `x -> g(f(x))`；核心 `>>` 尚未接入）

`inimerse --desugar` 是外糖的显式转换工具；外糖不应要求 VM 增加专用 opcode。

## V0.4 规则

1. 新增内糖必须有直接 parser/compiler 测试和解释器回归测试。
2. 新增外糖必须有脱糖前后等价性测试，并保证字符串、注释和嵌套结构不被误改写。
3. `Result` 的 `?`、管道 `|>`、lambda、函数组合和集合推导确定为内糖；当前 `|>`、Result `?`（unwrap 语义）与集合推导已实现，其余项目待接入。
4. `eidos`、`ed` 等对象/关键字别名默认属于外糖；对象模型稳定后再决定是否升级为内糖。
5. 集合到类型/对象的映射由翻译器负责，核心语言只保留可验证的基础集合和运行时值。

## 当前状态结论

仓库此前没有这份正式分类；本文件将其冻结为 V0.4 草案。现有实现中，`fn`、`print`、`&&/||`、`//`、`unless` 和 `say@target` 按外糖处理；区间、分号容忍、`++/--`、f-string 和尾逗号按内糖处理。
