> x be Z+ : 1

**`Z` 是无穷集合，`int32`/`int64` 只是区间**（`i.json#347` 用户 → `i.json#348` 助手，RESPONSE）：

> 或许a be Z已经是无穷精度了吗                （`#347`）

> ```
> int32 = [ -2^31 ~ 2^31-1 ]      # 用区间表示，而不是独立类型
> int64 = [ -2^63 ~ 2^63-1 ]
>
> # 精化
> positive = Z * [0, )            # 所有正整数
> byte = Z * [0~255]              # 字节
>
> # 编译优化
> x be Z * [0~255]                # 编译器知道范围 → 使用 uint8 快速路径
> y be Z                          # 编译器不知道范围 → 快速路径 + 溢出回退
> ```
>
> 建议**统一为 `Z`**，不再单独使用 `int` 表示定宽整数 …… **`Z` 就是无穷精度整数。没有 `BigInt`，没有 `int64` 限制，只有 `Z` 及其子集。**（`#348`）

`#348` 同时自列了代价，其中一条直接约束本设计（不得省略）：

> | **与 C ABI 交互** | 原生接口需明确 64 位，超出范围需转换 |

**表示窄化必须由编译期范围分析驱动**（`i.json#349` 用户 → `i.json#402` 助手）：

> 同理，其他的集合也应如此（包括降到二级特性的floatx）。或许能在类型指定后将取值范围尽量缩小（Z降级到子集int）或扩展。对于只有有限取值数的集合A=1,2,"A","S"，能让编译器压缩a be A指定的A的内存空间吗？如果能，则用户可以自定义特殊的小范围取值如byte      （`#349`）

> 如果编译器知道 `x ∈ Z * [0~255]`，它可以使用 `uint8_t` 而不是 `int64_t`。 …… **关键**：将无穷集合**尽量收窄为有界子集**进行优化，无法收窄时保持符号表示，仅在必要时插入运行时检查。（`#402`）

**类型别名与声明的统一**（`i.json#353` 用户 → `i.json#354` 助手，RESPONSE）：

> 特别地，定义type type1 = Z * [-1,1]后可以直接用type a 初始化了      （`#353`）

> ```python
> type byte = Z * [0~255]                    # 单字节整数
> type status = {"idle","run","jump","fall"} # 枚举状态
> type int32 = Z * [-2^31, 2^31)             # 32 位整数
> ```
>
> **`type T = 集合` 定义别名，`T x = 值` 声明变量。** …… **已删除**：`Float1..Float9`、`float1..float9` —— 用谓词替代：`type float2 = {x in R | x*100 in Z}`（`#354`）

**位宽可显式钉住，并由编译器校验**（`i.json#779`）：

> ```
> hp: N * [0~999] @bits(16)      # 16 位足够存储 0-999
> state: {"alive","dead","respawning"} @bits(2)   # 2 位枚举
> ```
>
> 编译器自动验证位宽是否足够存储集合的所有值。

**集合的编译期事实**（`i.json#400`、`#424`）：

> ```
> type Point = Z cartesian Z          # 等价于 {x: Z, y: Z}
> # count(Direction) == 4，编译期常量
> min_byte = min(Byte)          # 0
> max_byte = max(Byte)          # 255
> ```

**同一件事的另一种记法（与仓库冲突，见 §7）**（`i.json#322`，THINK）：

> ```
> x be (A ∪ B)    # 并集
> x be (A ∩ B)    # 交集
> x be (A \ B)    # 差集
> ```

## 3. 规范：`type` 用集合定义

**R1（唯一性）** 语言里没有「原语类型」。类型名是**集合表达式的规范名**，唯一形式是：

```
type NAME = <集合表达式>
```

集合表达式由内置集合（`Z` `N` `Z+` `Z-` `R` `Str` `Bool` `Any` `Empty`）、区间、有限枚举、谓词，以及 `+`（并）`*`（交）`-`（差）构成。`type` **不引入新的运行时值**（沿用 ROADMAP_3.1 §范围），展开与诊断保留别名名。

**R2（`Z` 是数学整数集，不是 `int64`）** `Z` 表示全体整数，**无范围上界**。`int`、`int32`、`int64` **都不是原语**，它们是 `Z` 的有界子集：

| 日常名 | 规范定义（唯一真值） | 基数上界 | 派生表示 |
| --- | --- | --- | --- |
| `u8` / `byte` | `N * [0, 2^8)` | 2^8 | 1 字节 |
| `i8` | `Z * [-2^7, 2^7)` | 2^8 | 1 字节 |
| `i16` | `Z * [-2^15, 2^15)` | 2^16 | 2 字节 |
| `i32` / `int32` | `Z * [-2^31, 2^31)` | 2^32 | 4 字节 |
| `u32` | `N * [0, 2^32)` | 2^32 | 4 字节 |
| `i64` / `int64` / `int`（历史名） | `Z * [-2^63, 2^63)` | 2^64 | 8 字节 |
| `Z` | 全部整数 | ∞ | 立即数 + 溢出切堆大整数 |

表里的「日常名」**只是一个别名**，其定义必须由一条 `type` 给出；别名之间不构成类型层级，**唯一的关系是集合的包含关系**。

**R3（位宽是派生的，不是类型的属性）** 「这个 `int` 是 32 位还是 64 位」在语言里**没有对象**——问的是「某个具名集合的基数／范围是多少」。表示宽度由集合在编译期派生。`@bits(n)` / `@bytes(n)` 是显式钉住**并要求编译期校验**的写法（`i.json#779`：`hp: N * [0~999] @bits(16)`；「编译器自动验证位宽是否足够存储集合的所有值」）。

**R4（范围收窄是优化的合法依据，不是正确性的依据）** `Z * [0~255]` 可收窄为 u8；**无法证明范围时保持符号表示并插入可定位的运行时检查**，不静默放宽（`i.json#402`）。静态证明失败必须产生可定位的检查（ROADMAP_3.1 §验收 3）。

**R5（固定宽度只许出现在 ABI／序列化边界）** `i64`/`u8` 这类名字**只在跨语言与线上格式边界出现**，且必须由一条 `type` 定义给出，理由直接来自 `i.json#348` 自列的代价那一行。语言内部不出现宽度。

**R6（溢出策略与集合一致）** 越出集合即报错，**不回绕、不静默**。当前实现已经是这个方向（`src/vm/vm.c:3134`／`:3239`／`:3276`／`:3301`／`:3344` 五处 `vm_throw_kind(vm, "numeric_overflow")`），**但上界是 int64**（`src/vm/vm.h:42` `union { long long ival; double fval; };`）——所以今天 `x be Z = 2 ** 200` 会按 int64 溢出报错，而不是按 `Z` 的数学定义成功。R2 要改的就是这一条。

### 3.1 用户所举写法与导出中已有的写法

用户举例：`type a = Z * [0,255]; b = 0 : a`。逐段对照：

| 段 | 导出中是否有出处 | 出处 |
| --- | --- | --- |
| `type a = Z * [0,255]` | **有** | `i.json#354` 的 `type byte = Z * [0~255]`、`type int32 = Z * [-2^31, 2^31)`；`i.json#267` 同时列了 `[1, 10]` 与 `[1 ~ 10]` 两种区间写法 |
| `b` 的初值为 `0` | **有** | `i.json#267` 的 `age be [0, 120] : 18`；`i.json#354` 的 `byte b = 42` |
| 声明形状 `b = 0 : a` | **没有逐字出处** | 导出里有三种形状：①`b be a : 0`（`#267`，**这已是仓库实现的 `OP_BE` 形式**）②`a b = 0`（`#354`：「`T x = 值` 声明变量」）③`b: a = 0`（`#358` 的 `hp : N * [0~100]` 与 `#667` 的 eidos 字段形式）。**`b = 0 : a` 是第四种形状**（类型后置、以 `:` 引出），导出中无先例 |

⇒ **`b = 0 : a` 不是这条指令里已经定下来的东西，是需要人裁定的一项**（登记在 §7.1）。

### 4.2 v0.6 要做（新增）

- [ ] **R1**：`type` 成为唯一的类型定义形式，并且**至少被编译期消费一次**（不再只是存一个全局值）。
- [ ] **R2**：`Z` = 任意精度（小整数快速路径 + 溢出切堆大整数）；`int`／`int32`／`int64` 一律降为 `Z` 的子集别名。
- [ ] **R3**：位宽从集合基数／范围派生；`@bits(n)`／`@bytes(n)` 显式钉住并编译期校验「位宽是否足够存储该集合的所有值」。
- [ ] **R4**：无法证明范围时保持符号表示并插入可定位的运行时检查（不接受静默放宽）。
- [ ] **R5**：ABI／序列化边界的固定宽度必须由一条 `type` 定义给出。
- [ ] **R6**：溢出语义与集合一致；`Z` 不再有 int64 上界。
- [ ] **消去「同一语义多决定点」**：`in`／子集／`be` 各收敛为**唯一**决定点（今天 C 内核与 VM 各一份）。这条与 [DECFY_DESIGN.md](DECFY_DESIGN.md) 是同一个问题。
- [ ] **迁移与诊断**：把现有 `a: int`、`a be Z`、`type NAME = …` 统一转换，并出诊断报告（ROADMAP_3.1 §声明语法与兼容性第 5 条）。
- [ ] **文档口径统一**：`docs/API.md:122-125` 用「已实现」描述 `src/types/`，并把 `type_registry_probe` 与真正走 `SetObj` 的 `type_collection_runtime` 并列成证据，容易被读成语言特性已接线；须与该文件 `:107` 的更准表述（「有限集合枚举／TypeSet 已成体系，但 `case try` 的开放错误域穷尽性证明仍不完备」）统一。

### 4.3 验收标准

1. 规范、编译器、VM 和 API 文档使用同一套集合语义（ROADMAP_3.1 §验收 1）。
2. 每个交付项都要有一条**能在 `main` 上失败**的进树回归（本仓库既有规则，见 [BOARD.md](BOARD.md) §5 各行）。
3. 可执行的判据样例：`x be Z = 2 ** 200` 成功；`x be Z * [0~255] = 256` 报错；`x be Z * [0~255]` 的字段在 `eidos` 里占用 1 字节（`i.json#354` §6.3 的三个字段 1+1+1 字节）。
4. **「`int` 是 32 位还是 64 位」在语言层不可提出**：`docs/` 与语法规范中不再出现未由一条 `type` 定义的宽度名（这是本条目标的可证伪形式）。
5. 集合运算在基准数据上有明确内存与延迟上限（ROADMAP_3.1 §验收 4）。

### 4.4 非目标

- v0.6 不删除 `Float1`–`Float9` / `float1`–`float9`（沿用 ROADMAP_3.1 §非目标；`i.json#354` 曾把「已删除」写进 v3 文档，**那不是已落地的裁定**）。
- 不把不可判定谓词伪装成编译期类型证明。
- 未出规范与迁移工具前，不改变 `in` 的既有语义。
- v0.6 不承诺 BigInt 的性能目标，只承诺**语义正确**（R2/R6）。

## 6. 前置与依赖

- **与 DECFY_DESIGN 同源**：「同一个语义有多个独立决定点」在集合化上至少有三处（`in`／子集：C 内核与 VM；`be`：编译器与 VM 各自预置内置集合全局，见 `src/compiler/compiler.c:2861-2864` 与 `src/vm/vm.c:1390-1404`）。**R1–R6 的收敛必须与去 C 化设计用同一套决定点清单**，否则会出现「去 C 化之后仍然两份答案」。
- **与 v3.1 文档的关系**：`archive/ROADMAP_3.1.md` 内容不变，仍是规格来源；本文改的是**时间表**与**规范条文形式**。
- **与 ABI 的关系**：R5 决定 `i64` 这类名字是不是唯一的宽度出口；在 R5 落地前，任何「`int` 到底是几位」的问题都无法在语言层回答。

## 7. 未决（本轮**没有**结论，不得当成已定）

1. **`b = 0 : a` 这个声明形状**。§3.1 已证它在导出中**无逐字出处**；与它冲突的既有形状有三种（`b be a : 0` 已实现、`a b = 0`、`b: a = 0`）。要定必须由人裁定——注意 `:` 在 `be` 里**已经被初始值占用**（`name be set : init`），所以形状 ③ 与「`be` 的初始化」是同一个符号的两个用途。
2. **`∪`／`∩`／`\` 还是 `+`／`*`／`-`**。导出（`#322`）用数学符号，仓库用 ASCII 运算符，`docs/SYNTAX.md` 未采纳前者。两者并存会让同一份脚本有两种记法。
3. **`FloatN`／`floatN` 的去留**。`i.json#354` 写「已删除」，ROADMAP_3.1 §非目标写「v3.1 之前不删除」，仓库里仍在且被测试覆盖。三处表述**互相矛盾**，本目标不预设结论。
