# Inimerse / Infiverse 版本路线图（v0.4–v0.6）

本文将 `future/` 中的愿景拆分为可交付、可测试的版本。v0.3 仍以跨平台核心、UPP/CRP、`.vverse` 和工作台基础能力为前置条件。

## v0.4：运行时性能、Eidos 与包生态

目标：让 Inimerse 从“可移植运行时”进入“可扩展开发平台”。

> 集合化类型系统（谓词集合、类型即集合、集合映射）不属于 v0.4，统一延期至 v3.1；v0.4 仅维护现有基础集合的兼容性。

实施状态（当前）：参数 v2、VFS 基础和 `inim` 离线包闭环已进入 `main`；集合/Result/Eidos、JIT 和发行渠道仍未完成。

Result 运行时原语已加入：`ok(value)`、`err(error)`、`is_ok(result)`、`unwrap_or(result, fallback)`；第一版以字典值表示，语法糖 `?` 和编译器穷尽检查仍待实现。

性能基线工具：`python tools/v04_bench.py <script.im> -e <inimerse> -n 5`，可用 `--json` 输出供 CI 比较；在 JIT 后端接入前先固定解释器基线。

JIT 策略开关已预留：`--jit=off|template|optimized`（当前两种非 off 模式安全回退解释器，待后续接入机器码后端）；`jit_mode_probe` 锁定模式解析契约。

当前 `simple.im` 在 WSL/POSIX 解释器基线约为 196 ms/次（3 次样本，机器相关，仅作相对比较）。

### 运行时与 JIT

- 热点计数器、基准套件和性能回归门禁。
- 常量折叠、死代码消除、循环不变式外提、字节码 peephole 优化。
- 模板 JIT（整数/浮点基础算术）与类型特化 JIT，失败时安全回退解释器。
- Eidos 对象布局、属性偏移表、vtable 和单态内联缓存。
- NaN boxing、短字符串、Rope 字符串与分代/增量 GC 进入实验特性，默认保持兼容路径。

验收：基准结果可重复；JIT 代码与解释器结果一致；无特化命中时性能和内存不劣于 v0.3；提供 `--jit=off|template|optimized` 开关。

### Eidos 面向对象化

- `class`、实例、构造器、方法、继承/组合和接口契约。
- `get/set`、Mixin、sealed/frozen/invariant 的语义草案与运行时检查。
- 明确 `this`、可见性、方法解析顺序、循环继承错误和热更新失效规则。
- 编译器错误包含源文件、行列号和可操作修复建议。

验收：对象语法规范、AST/字节码测试、序列化兼容性测试和热更新回归全部通过。

### 包管理器与生态

- `inim package init/add/remove/update/install/publish` CLI。
- 包清单、语义化版本、锁文件、平台/ABI/能力声明。
- 本地缓存、内容寻址、依赖冲突解释和离线安装。
- `.vverse` 与普通库包统一索引格式；签名验证默认开启，可显式配置信任源。

当前实现入口：`python tools/inim.py` 已提供离线 `init`、`pack`、`install`、`list`、`add`、`remove`、`run`、`publish` 闭环。`.inim` 是 ZIP 容器，包含 `manifest.json`；安装写入 `.inim-cache/` 和 `lock.json`，支持本地路径依赖并拒绝路径穿越。`publish` 生成包和 `index.json`（含 SHA-256、SemVer 版本与引擎约束）。签名和远程 registry 仍待后续迭代。

验收：从空目录安装一个带依赖的示例项目；断网可从缓存复现；篡改包、ABI 不兼容包和恶意路径均被拒绝。

## v0.5：编译化、底层接口与跨语言迁移

目标：提供稳定的编译产物和可控的 FFI，使现有项目能够渐进式迁移。

### 编译器与底层接口

- 完整字节码格式版本化、增量编译和可复现构建。
- AOT 编译实验链路（先支持 C ABI，再扩展 LLVM/Wasm 后端）。
- 稳定 Native ABI：整数、浮点、字符串、数组、结构体、错误和所有权规则。
- `native` 模块声明、能力沙箱、动态库加载策略及 Windows/Linux/macOS 差异隔离。
- 调试信息、崩溃回溯、符号表和性能剖析接口。

验收：同一项目可生成解释执行、AOT 和 Wasm 三种产物；ABI 版本不兼容时构建期明确失败；跨平台 CI 可复现。

### 跨语言 API 与迁移工具

- C/C++：头文件扫描、C ABI 包装、CMake 项目导入和 RAII/所有权适配模板。
- Java：JVM 调用桥、类/方法映射、异常转换和 Gradle/Maven 依赖导入。
- Python：模块扫描、类型提示读取、CPython/ABI3 扩展桥和异步调用适配。
- 通用 IDL/绑定生成器：从接口定义生成 Inimerse、C、C++、Java、Python 胶水代码。
- 迁移报告：自动识别不可直接转换的语法、依赖和运行时假设，提供分阶段改造清单。

验收：每种语言至少有一个可运行示例；基本数据类型、错误、回调和异步边界有双向测试；迁移工具能生成报告而不是静默改变语义。

## v0.6：Inim OS、Infiverse 规范与 2D 引擎

目标：把运行时能力提升为操作系统级服务和统一内容平台。该版本依赖 v0.5 的稳定 ABI/编译链。

### Inim OS for Windows/Linux

- 用户态服务、任务/进程模型、权限与沙箱、虚拟文件系统（VFS）。
- 统一设备/输入/窗口/音频/网络 PAL；Windows 与 Linux 后端可替换、可测试。
- 包、服务和 Verse 的生命周期管理；日志、更新、回滚和崩溃恢复。
- 先以 Windows/Linux 宿主模式交付，再评估独立引导与内核化范围。

验收：同一 Inim OS 服务包可在 Windows 和 Linux 启动；权限越界、路径逃逸和资源耗尽均有测试与可观测错误。

### Infiverse 内核及规范

- 固化 UPP、CRP、VDP、ABI、能力模型和内容寻址规范，发布版本化 RFC。
- Verse/Layer/Block/Cell 空间模型、传送门寻址和事件时序的参考实现。
- Hub、客户端、服务器和工具的互操作性测试套件。
- 规范合规标识、兼容矩阵和长期弃用策略。

验收：至少两种独立实现通过互操作测试；协议扩展保持向后兼容；规范文档与测试向量同步发布。

### Infiverse 2D 游戏引擎

- 场景、精灵、瓦片地图、碰撞、相机、动画、音频和输入抽象。
- 确定性更新循环、存档/回放、脚本热重载和资源导入管线。
- `.vverse` 作为项目/分发格式，支持签名、依赖和增量资源缓存。
- 编辑器工作台：场景树、属性面板、脚本编辑、运行/停止、诊断和打包发布。

验收：可创建、运行、保存并发布一个完整 2D 示例游戏；Windows/Linux 行为一致；帧时间、内存和资源加载有基准数据。

## 跨版本原则

1. 协议和 ABI 优先于实现，新增字段必须向后兼容。
2. 实验特性通过显式开关启用，不能破坏默认解释器路径。
3. 每个版本都必须提供迁移指南、回滚路径和可重复测试夹具。
4. 性能目标以基准数据为依据，不以未经验证的理论倍数作为承诺。
