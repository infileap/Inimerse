## 1. 位运算（已裁定）

### 1.1 决定

**位运算以函数形式提供，拼写与 Inim 汇编助记符一致**：

| 名字 | 含义 |
| --- | --- |
| `bit_and` | 按位与 |
| `bit_or` | 按位或 |
| `bit_xor` | 按位异或 |
| `bit_not` | 按位取反 |
| `shl` | 左移 |
| `shr` | 右移 |

**归 v0.7，不进 v0.6。**

### 1.2 为什么是函数形式，不是运算符

这一条**不是取舍，是被测量逼出来的** —— 四个可能的运算符拼写，今天在词法上**全部不可用**：

| 拼写 | 今天的词法状态 |
| --- | --- |
| `&` | `TOK_UNKNOWN`（没有规则） |
| `\|` | `TOK_PIPE` —— **已被 `case` 的 `\|` 守卫占用** |
| `>>` | `TOK_COMPOSE` —— **已被函数组合 `f >> g` 占用** |
| `<<`、`^` | **完全没有词法规则** |

`|` 与 `>>` 是**已经在用的**记号：把它们改成位运算，等于改掉 `case` 守卫与函数组合的语法。`&` / `<<` / `^` 可以新造，但那样同一个概念会有两种拼法。⇒ **函数形式是唯一不破坏现有语法的形式。**

### 1.3 为什么拼写跟汇编助记符走

第 2 节那份提案用的是 `bit_and r_a, r_b` 与 `shl r_a, 3`。两层用同一个名字，意味着**从 `.im` 落到汇编时不需要一次名字翻译** —— 而如果两层名字不同，「这两件事是同一件事」就只能靠文档记着。

### 1.4 今天的现状

- **一个位运算内建都没有**：`band` / `bor` / `bxor` / `bnot` / `shl` / `shr` 零注册。
- **真实树里位运算写法零用户**。
- ★ `docs/SYNTAX.md` 里那句「**要做位运算只能走内建函数**」**今天是假的** —— 内建一个都没有。⇒ **这一节的决定正好把它变成真的**：它被写下时不是描述，是预言。

### 1.5 位宽与溢出（**已裁定 A**）

★ **两个未决一起被裁掉：`Z` 是任意精度，位运算按补码语义定义到无穷位。**

- **位宽**：`Z` **任意精度**。⇒ `bit_and`/`bit_or`/`bit_xor`/`bit_not` 按**补码**语义定义到无穷位（`~x = -x - 1`）；`x << n` **会变长**（`1 << 1000` 就是一个 1001 位的数）；`x >> n` 是**算术右移**（补码语义延伸到无穷位，所以负数右移仍是负数）。★ **这与 `Z+`/`N`/`N * [0~999]` 自洽** —— 它们全都是 `Z` 的子集，而「子集」这件事只有在 `Z` 本身任意精度时才不需要附加说明。
- **溢出与符号**：★ **这个问题不存在。** 任意精度下 `shl` 永远不会溢出 ⇒ 「回绕／饱和／`Result`」三选一**没有对象**。提案里 `div` 给 `Result(Z, DivisionByZero)` 而 `shl` 给裸 `Z` 的那个不一致，**因此也不需要解决**：`div` 要 `Result` 是因为**除以零是一个错误**，不是因为溢出。

★ **这一裁定让 §2.11 的七条保证里有一条对 `Z` 变成空的**：`overflow`（算术溢出）在任意精度整数上**没有可放弃的东西**。⇒ **两节是自洽的** —— §2.11 的红方向①说的正是「点名了，但这段代码里没有任何一处本来会被它拒绝 ⇒ 拒绝」，所以 `@unsafe(overflow)` 写在纯 `Z` 的代码上**本来就该被拒**。`overflow` 留在七条里，是因为将来若有**定宽类型**（`u64` 那一族）或浮点，它在那里有对象。

★ **边界**：这一裁定**只回答了 `Z`**。`bit_and` 作用在 `float`／`Bool`／集合上是什么，本文件没有说 —— 也不该由这一裁定顺带决定。
- **与集合约束的关系**：`U380` 要「集合约束用于汇编进一步择优」；定宽是这件事的前提。

### 1.6 验收（**本节此前只有裁定，没有验收 —— 这一节是补上的**）

`V1`/`V2` 各有一条**能红**的断言，**不需要任何后端**：

| 断言 | 为什么它能红 |
| --- | --- |
| 六个名字在**两个平台**的内建注册点里都存在 | 今天**零注册**（§1.4）⇒ 现在是红的 |
| `bit_not x == -x - 1` 对正、负、零都成立 | 它把「补码语义定义到无穷位」写成了一个**等式**，而不是一句描述 |
| `1 << 1000` 的十进制位数是 **1001 位** | ★ **它钉住的是「会变长」** —— 一个定宽的实现在这里会回绕，而回绕**不会报错**，只会给出另一个数 |
| `-8 >> 1 == -4`（而不是 `2147483644`） | ★ **它钉住的是「算术右移」** —— 逻辑右移会给出一个正数，而**两者都合法、都不报错** |
| `bit_and` 作用在 `float` 上**必须有一个明确的结局** | ★ 今天**没有裁定**（§1.5 的边界）⇒ 这条断言现在**无法写**，**而「无法写」本身要写下来** —— 否则它会被读成「已经覆盖了」 |

★ **最后一行是这一节的要点**：**一个没有裁定的边界，它的正确形态是一条写不出来的断言加上一句「这里没有裁定」，不是一句沉默。** 沉默在验收清单里与「已通过」长得一样。

### 2.2 那份提案

2026-10-05 贴出的《新汇编语法设计》。五条核心原则：类型化寄存器 / 所有权感知 / 集合运算直接映射 / 安全内存访问（借用而非裸指针）/ NaN Boxing 透明。语法骨架：

```
@asm x86_64 {
    r_a: Z+ = load a
    r_sum: Z = add r_a, r_b
    flag_positive: Bool = in r_sum, Z+
    jump_if flag_positive, @positive_label
    store result, r_sum
}
```

并声称「**同时保留传统汇编的全部底层控制能力**」，需要时进 `@unsafe` 用裸指针（`addr_of` / `ptr_add`）。

### 2.3 两处矛盾（**这一节存在的理由**）

**① 方向相反 —— 已裁（人类裁定 C）：两层都要。**

`U367`：「我希望汇编能**直观看到与硬件操作的对应关系**。」
提案的核心原则：**「类型化寄存器」+「编译器自动分配底层硬件寄存器」**（`r_a: Z = load a`）。

★ **类型化寄存器把硬件藏起来了，而人类要的是看见它。** 提案第十一节说「同时保留传统汇编的全部底层控制能力」，但「类型化寄存器 + 自动分配」**恰恰是不保留的那一半**。⇒ 这两句不能同时成立。人类裁定 **C：写两层**。

**层一（提案写的那层，保留）：`@asm`。** 寄存器是**虚拟的**、带集合类型、由编译器分配。它承诺的是**安全**（所有权、集合约束、NaN Boxing 透明），**不承诺**与硬件的对应关系。

**层二（`U367` 要的那层，新增）：物理寄存器层。** 寄存器是**物理的**，命名与硬件对应（`rax` / `rdi` / `xmm0` / …），集合类型只做**检查**、不参与分配。它承诺的是**看得见**，代价是失去层一的那些保证。

**★ 名字已裁（人类裁定 C）：`@asm.phys`。** 它与「**物理**寄存器」逐字对应，也与层一的「虚拟寄存器」形成干净的对照。★ **`raw` 被否掉的理由值得留下来**：`raw` 在 `src/` 里**已经是一个类型的名字**（会把两件无关的事联系起来），而且「raw」读起来像「原始／**不安全**」—— 而层二**不是不安全的**（§2.11 刚把这两件事分开）。⇒ **名字会替设计说话，所以它不能随便取。**

**C 的代价写在明处**：两套语法要**同时维护** —— 两个解析路径、两个 IR 形状、两条测试线。这是它比 (a) 或 (b) 都贵的地方；而它贵得值，因为 `U367` 与提案要的是**两件不同的事**，各自都能实现，冲突只在「一套语法同时做到」。

**一条验收（照本仓库的规矩）**：两层必须**能被一条测试彼此分辨** —— 一条只写虚拟寄存器的 `@asm` 与一条只写物理寄存器的程序，不能产生同一份产物；且「层二承诺硬件对应」这句话要有一条**能红**的对照（把某个物理寄存器名换成一个不存在的名字：层二应当拒绝，层一应当**根本不认识**这个名字）。

**与 `@unsafe` 的关系是正交的。** 提案里的 `@unsafe { ptr: *Z = addr_of arr[0]; }` 解决的是**裸指针**，不是**寄存器可见性**；层二不依赖 `@unsafe`，`@unsafe` 也不依赖层二。**这两件事不要合并。**

**② 它用了已经否掉的拼写。**

提案 §5.2 逐字 `Ok(r_sum) => store result, r_sum` —— 而 `=>` 已裁定改成 `:`（且 `:` 是仓库现行状态）。

### 2.4 仓库现状：零

- `@asm` 全仓**零命中**。
- **源码里没有任何汇编后端**：`__asm__` / `inline asm` / `asm` 关键字零命中。
- ★ 仓库里**唯一一条与汇编有关的规则说的是「汇编不进来」**：迁移工具把 inline assembly 逐字标为 `inline assembly is not convertible`。
- `docs/PLAN_V06.md` 只把 `U218` / `U219` 记在 §5.4「与三件都无关，但必须记着」（「未实现」）。

### 2.5 口径冲突（台账已记）

`U368` 问「这样在性能上比得上传统汇编吗」；`U375` 直接**断言**「战胜普通手写汇编」；`U376` 又把 `U368` 的问题**原样重问一遍**（`U368` 与 `U376` 逐字重复）。⇒ **一个还没做的系统，它的性能已经被断言为「战胜」，而同一个问题又被问了一遍。**

**已裁（人类裁定 C，再裁定 A）：先测基线，再定门槛。**

**门槛（裁定 A）**：

> **汇编线的实现，在同一个基准上，不得慢于 C `-O2` 的 5 倍。**
> **且必须同时给出解释器与 AOT 两条数。**

两条附加要求：

1. **倍数定在「干活时间」上，不是墙钟** —— 必须先扣掉启动（今天的启动占墙钟约 30%，按墙钟定的门槛量到的首先会是启动）。
2. **必须同时给两条数** —— 只报 AOT 会掩盖「解释器才是默认路径」这件事；只报解释器会掩盖「编译到底有没有用」。

★ **这个门槛今天还无法被执行**：`U377` 要三列，而「inimerse 汇编」那一列**不存在**。门槛是给将来那个后端定的，不是给今天定的 —— 今天它只能用来**说明差多远**。

下面是测出来的东西 —— ★ **它是基线，不是门槛。**

### 2.6 今天的基线（实测）

**观测点**：工作目录 `/home/sakiko/inimerse`，HEAD = `3a9c2a3`，产物 `build/inimerse`（Release）。

**基准**：`n = 0; for i in range(1, 2000000) { n = n + i }`。四种跑法各取 3 次里最快的一次；另有一个**启动基线**（空脚本 `x = 1`），用来把启动从「干活」里分出来：

| 跑法 | 墙钟 | 扣掉启动后 |
| --- | --- | --- |
| `build/inimerse bench.im`（解释器） | **682 ms** | 682 − 207 = **475 ms** |
| `build/inimerse bench.inim`（`compile` 的产物） | **614 ms** | 614 − 207 = **407 ms** |
| 启动基线（空脚本） | **207 ms** | —— |
| C `-O0` | **26 ms** | |
| C `-O2` | **17–18 ms** | |
| C `-O3` | **17 ms** | |
| **手写汇编**（普通循环） | **18 ms** | |

C 侧用 `long` 累加、**N 由 `argv` 传入**（这样 GCC 不能把它折成闭式 —— 实测 `objdump` 里循环还在，`jle` 与 `jne` 各一条）。三条路径给出**同一个答案** `1999999000000`。

**读数**：

- 解释器 vs C `-O2`：墙钟 **40×**，只算干活 **28×**。
- AOT vs C `-O2`：墙钟 **36×**，只算干活 **24×**。
- ★ **AOT 只比解释器快 1.17×**（干活 475 → 407 ms）⇒ **「编译」今天几乎不买速度。**
- ★ **启动占 207/682 = 30%**（解释器）、207/614 = 34%（AOT）⇒ **任何按墙钟定的门槛，量到的首先会是启动。**

★ **最重要的一条**：`compile` 的产物被 `file` 判为 **`data`**、715 字节 —— 它是**序列化过的字节码容器，不是机器码**。⇒ `U197`/`U198` 那句「编译后对标 C++ O2/O3 **并嵌入汇编**达到原生速度」里的**那个「编译」今天不存在**；今天存在的「编译」是把字节码存进文件、省掉解析。

**`U377` 要的那三列，今天是这样**：

| `U377` 的列 | 今天 |
| --- | --- |
| inimerse **非汇编** | **有数**（上表解释器与 AOT 两行） |
| inimerse **汇编** | ★ **无** —— 不是 `0`，是**不存在**（`@asm` 零命中、无汇编后端） |
| **传统汇编** | **有数** —— 手写汇编 **18 ms**（与 C `-O2` 同速） |

★ **「无」与「0」必须分开写**：汇编那一列是「没有这个东西」，不是「测得 0」—— 它们今天在表里长得一样，而处置相反（前者要去做，后者要去查）。

**方法的三条边界**：

1. 这是**单条整数循环**，不含函数调用、分配、字符串、IO ⇒ **它只量了字节码派发与算术**，不量语言的其他部分。
2. `.im` 的数是 NaN 装箱的 `Value`，C 的是裸 `long` ⇒ **两个「加法」不是同一件事**，这个比值里混着表示形式的差别。
3. **启动那 190–207 ms 的构成没有分解** —— 只知道空脚本要这么多，不知道里面各占多少。换一个构建配置，这一列会变。
4. ★ **抖动约 ±8%**：同一个 HEAD、同一台机器上，解释器这一列先后读到 **589 / 682 / 601 ms**，启动读到 **194 / 207 / 190 ms**（这期间别的会话在跑）。⇒ **门槛的余量必须大于抖动**，而 5× 的余量远大于 8%。

**手写汇编那一列是怎么来的**：x86-64、`argv` 取 N、`n += i` 的朴素循环（`cmp`/`jge`/`add`/`inc`/`jmp`），用 `gcc -no-pie -O2` 汇编链接。**它是「普通手写汇编」的字面意思** —— 没有展开、没有向量化、没有用任何领域知识。⇒ **它和 C `-O2` 同速（18 ms）** 这件事本身是一条读数：**在这个基准上，`-O2` 已经到手写水平，所以「战胜普通手写汇编」这个目标的对照物，是 C `-O2`，不是某种很差的汇编。**

### 2.8 往返：`.im` → 汇编 → `.im`（**已裁定 A**）

**裁定**：把「`.im` → 汇编 → `.im` **语义等价**」定成汇编线的一条**验收**。

**它绑住的是三条原话** —— 它们其实是同一件事：

| 编号 | 逐字 | 它在往返里的角色 |
| --- | --- | --- |
| `U365`(`#732`) | 「不妨让inimerse自己准备汇编**和反编译器**」 | 提供两端 |
| `U371`(`#744`) | 「对inimerse汇编码**反编译**用于优化」 | 提供回来的那一段 |
| `U094`(`#189`) | 「通过接口使难以转.im的源码直接或间接运行，又或者**转汇编再转.im**」 | **给出判据** |

### 判据的准确形状

**「语义等价」不是「文本相同」。** 汇编里没有注释、没有结构、没有变量名，所以文本相同是不可能的，而且**不应该**是目标。判据必须落在**可观察行为**上：

> 同一组输入 ⇒ **同一组输出**、**同一组错误**、**同一个退出码**。

### ★ 这条判据最容易被骗过去的地方

**如果 `.im` → 汇编这一步把原始源码塞进汇编产物里**，那么 `.im` ← 汇编 只要把那段源码读出来，往返就**自动成立**，而它什么都没证明。

⇒ **验收里必须有一条**：往返测试要在**剥掉任何内嵌源码之后**仍然成立（或者直接断言：汇编产物里**不含**原始 `.im` 的文本）。这一条不是补充，**它是这条判据能不能红的前提** —— 没有它，一个只负责「把原文存起来」的实现会全绿。

### 红对照（照本仓库的规矩）

往返测试必须有一条**能红**的对照：拿一个夹具，**在汇编那一侧做一处会改变行为的改动**（改一个立即数、改一个跳转目标），再反编译回来 —— **往返必须失败**。若它仍然「通过」，那么这条判据量的是「反编译器能不能跑」，不是「它反编译得对不对」。

### 今天的状态

**没有任何一段可以往返的东西**：没有汇编后端（`@asm` 零命中）、没有反编译器。⇒ 这条判据今天**只能被写下来，不能被跑**。它的用处是：**在有人开始写反编译器之前，先把「什么算对」写清楚** —— 否则第一个反编译器会定义什么叫对。

### 它不证明什么

- 不证明产物**可读**（给人看的可读性与往返正确性是两件事）。
- 不证明**优化**（`U371` 说的「用于优化」是另一件事：往返正确是它的前提，不是它的内容）。
- 不证明 `.im` → 汇编是**可逆**的 —— 编译本来就是有损的，这里承诺的是**行为**可逆，不是**程序**可逆。

### 2.9 内联汇编与「直接调用汇编」是两件事（**已裁定 A**）

**裁定**：**两个机制，不合并。**

**机制一 —— 内联（`@asm`）**：写在 `.im` 函数体里的一段。它与周围的变量、所有权、类型系统**共享上下文** ⇒ **它必须懂 `.im` 的值表示**（NaN 装箱、集合类型、借用）。

**机制二 —— 外部调用（`U140`）**：调用一个**已经存在**的汇编目标（一个链接进来的目标文件、一个 `extern` 符号、一段系统调用）。它**只需要一条调用约定**，不需要懂 `.im` 的值表示。

**为什么不能合并**：它们的**依赖表不一样**。合并会让内联那一侧被迫背上一整套外部调用约定，或者让外部调用那一侧被迫懂值表示 —— 两边都要为对方的约束付账。

### 仓库里那条反方向的证据，正好只挡其中一半

迁移工具把 inline assembly 逐字标成 `inline assembly is not convertible` —— **仓库唯一一条与汇编有关的规则，说的正是「不转换内联汇编」**。

⇒ ★ 它挡的是**机制一**。**机制二（外部调用）它一点都不挡** —— 因为外部调用根本不经过「把源码转成 `.im`」这条路。**一条规则挡的是哪一半，取决于那半边的形状，而不是取决于它的名字里有「汇编」两个字。**

### 机制二真正的工作量在哪

不在调用，**在边界**：`.im` 的值是 NaN 装箱的 `Value`，外部汇编看到的是寄存器与内存。⇒ **必须有人写下「值怎么过界」**：一个 `Z` 传进去是什么寄存器、一个 `array` 怎么传、返回值怎么装回来、谁负责装箱/拆箱。

**这条要能被断言**：一个外部的目标文件里的函数，被 `.im` 调用，**参数与返回值两侧都要有断言**（不是「能调用」，是「调用之后两边的值都能被读出来并且相等」）。

### 2.10 `U380`：集合约束必须被指令选择读到（**已裁定 A**）

**裁定**：写成**后端的一条设计约束** —— **指令选择必须能读到集合约束**；并且**验收要能证明它读了**。

**判据的形状**（干净得少见）：

> **只改集合约束，不改代码 —— 产物必须不同。**
> 例如把 `x: Z` 改成 `x: Z+`：`Z+` 是正整数，符号检查可以省掉。

这条判据的好处是它**不需要先有完整的优化器** —— 它只要求「指令选择读过约束」这一件事能被看见。

### ★ 但「产物必须不同」这句话，单独写下来是**不够的**

一个只断言「两次产物不同」的测试，会被**任何不确定性**通过 —— 产物里多一个时间戳、一个随机的寄存器分配顺序、一个随机的节名，它都会绿。⇒ **断言必须点名是哪一处不同**：

> `Z` 的版本里**有一条范围/符号检查**，`Z+` 的版本里**没有**（或者：指令数少了那条检查，而不是「少了几个字节」）。

**要能红的对照**：把指令选择改成**忽略**约束 ⇒ 这条断言必须失败。

**反方向也要有**：**不改约束**（同一个程序跑两次）⇒ 产物必须**相同**。否则「产物不同」这个断言量的是不确定性，不是约束。

### 为什么不是 R3

R3（一种类型可以声明自己的表示与宽度）是**语言侧**的声明：类型怎么说自己。`U380` 说的是**后端怎么用它**：指令选择读不读得到。**这两件是不同的问题** —— 一个类型可以正确地声明了自己的宽度，而指令选择完全不理它，两边都不报错。

### 今天的状态

**连一个能读约束的指令选择器都没有。** ⇒ 这条是给将来那个后端的约束，今天只能写下来。

★ **它给 `U380` 落了位** ⇒ 十一条里现在**只剩一条没有落点**：`U371` 的「反编译**用于优化**」（往返正确是它的前提，不是它的内容）。

### 2.11 `@unsafe` 是一个标记，不是一层（**已裁定 A**）

**裁定**：`@unsafe` **标记「这一段放弃了哪几条保证」**，语法本身不换。**它必须点名。**

**为什么**：**「不安全」不是一条可以被检查的性质，而「放弃了借用检查」是。** 一个只写 `@unsafe` 的块，读它的人无法知道什么被放弃了；一个点了名的标记，可以被检查「你点的那条，在这段代码里真的被放弃了吗」。

**层二（看得见硬件）不需要 `@unsafe`** —— 看见寄存器和放弃安全保证是**两件事**。把它们绑在一起，会让「想看硬件」变成「必须先声明不安全」。

### 伪代码（**这是设计，不是今天的语法**）

**① 标记必须点名**

```text
@unsafe(borrow, bounds)
func read_raw(arr: array(Z), i: Z) -> Z {
    return arr[i]                 # 这一段里，借用检查与越界检查被放弃
}

@unsafe                           # 不点名 —— 拒绝
func f(arr: array(Z), i: Z) -> Z { return arr[i] }
# error: '@unsafe' must name the guarantees it drops
```

**可以点名的保证**（每条都对应一个**能被单独关掉**的检查）：

| 名字 | 关掉的是 |
| --- | --- |
| `borrow` | 借用/所有权检查（含 `ptr_add` 这类指针运算） |
| `bounds` | 数组/集合的越界检查 |
| `types` | 值的重新解释（把一个类型当另一个用） |
| `init` | 读未初始化 |
| `sets` | 集合约束检查（`Z+`、`N * [0~999]`）—— ★ 与 §2.10 同一条 |
| `overflow` | 算术溢出 |
| `null` | 空值检查（`?.` / `??` 那一族） |

**② 点名必须被挣到（红方向一）**

```text
@unsafe(bounds)
func safe_looking(arr: array(Z), i: Z) -> Z {
    if i >= 0 and i < len(arr) {
        return arr[i]             # 这里没有任何一处本来会被越界检查拒绝
    }
    return 0
}
# error: this block declares @unsafe(bounds), but nothing in it would be
#        refused by the bounds check -- the marker is decoration
```

**③ 用了但没点名（红方向二）**

```text
func f(p: *Z) -> *Z {
    return ptr_add p, 1
}
# error: pointer arithmetic needs @unsafe(borrow), which is not declared
```

**④ 层二不需要 `@unsafe`**

```text
@asm.phys {
    mov rax, rdi
    add rax, 1
    ret
}
# 没有 @unsafe。层二放弃的是「编译器替你分配寄存器」——
# 那是一条便利，不是一条保证。

@asm.phys {
    @unsafe(borrow) {             # 层二里做裸指针运算，仍然要点名
        mov rax, [rdi]
    }
}
```

**⑤ 检查器怎么判**

```text
func check_unsafe_block(block):
    named = block.unsafe_guarantees()
    if named is empty:
        error("'@unsafe' must name the guarantees it drops")

    for g in named:                                   # 方向一：点了没用
        if not block.would_be_refused_without(g):
            error("declares @unsafe(" + g + "), but nothing here "
                  "would be refused by it")

    for g in block.guarantees_actually_needed():      # 方向二：用了没点
        if g not in named:
            error("this code needs @unsafe(" + g + "), which is not declared")
```

### 这条判据诚实的地方

- **`would_be_refused_without(g)` 是一个近似。** 精确判定「这段代码里有没有东西本来会被拒绝」与停机问题同类 ⇒ **它必然有假阳与假阴**。⇒ 检查器必须**自报它是近似**（说清它考虑了哪些形状），否则「没有报错」会被读成「没有问题」—— 而这两件事不一样。
- **`guarantees_actually_needed()` 同理** —— 它只能看见**它能看见的形状**。
- ★ **今天 `.im` 里没有任何一条这样的保证被实现成「可以单独关掉」** ⇒ 这一节是**设计**，不是今天的语法。它的用处是：**在有人实现 `@unsafe` 之前，先把「什么算用对了」写清楚。**

### 2.12 `U371` 的「用于优化」：给人走的回路（**已裁定 A**）

**裁定**：**给人改，不是给机器改。**

**回路**：反编译 → **人读懂** → 手工改汇编 → 重新汇编。

**判据（两半，分开写）**：

| 半边 | 能不能自动跑 |
| --- | --- |
| **改过的汇编重新汇编后，行为相同** | ★ **能** —— 与 §2.8 同形的断言 |
| **真的更快** | ★ **能** —— 因为「更快」今天有前值（§2.6 的基线表） |
| **人能读懂** | ★ **不能** —— 「可读」不是一个能自动断言的性质 |
