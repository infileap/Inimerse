# Inimerse v0.6 —— 错误码（域 · 整数码 · 穷尽性）

> **状态**：设计已裁，实现未开始。
> **裁定人**：用户，2026-10。**执笔**：`exact-otter`。
> **对本文档自身的引用请引节号（§2、§4.3），不要引行号** —— 本文档会被改动，行号会失效。

## §0 一句话

**错误码是一个字节**：高半字节是**域**，低半字节是**域内成员**；`0x00` 是 ok。
**域是一个小集合**，处理它的人只面对这一小集合；**编译器能证明「这个小集合全处理了」**，证不出来就点名缺谁。
★ **这条链今天已经通了 —— 通的只有最后一步：成员是字符串，不是整数码。**

## §1 为什么写这一份

### §1.1 用户的三条裁定（逐字）

1. 「**用半字节（0~255）包含这些码（已有 ok 对应 0，其他要方便用）**」
2. 「**整体是一个大集合，下面分成多个小集合（最好每个至多 16 个码；如 FileError 之类的，文档错误处理只需要针对单个小集合，编译器检测到对应错误集合所有都有处理就能安全过关）**」
3. 「**另外需要速查整数码的途径，或许 inimerse.exe 可以输出对应码、域**」

### §1.2 三个待定点的裁定（逐字回字母）

| 点 | 裁定 | 含义 |
|---|---|---|
| ① `catch` 怎么声明处理哪个域 | **D** | **保持今天的守卫式不动**，只把成员从字符串换成整数码 |
| ② 「每域 ≤ 16」由谁守 | **C** | **C 的本意是「两条都要」；实测之后是【一条】** —— 见 §3.3：半字节的约束在枚举层【之上】，一条域守卫就够 |
| ③ 旧码 1001–2307 是否保留 | **不留** | 表里不设 `legacy_code` 一栏 |

### §1.3 ★ 这一份不是新造需求 —— 它要改的那套，今天已经跑起来了

**逐项对表**（这不是推测，是 `vtest/` 里在跑的夹具）：

| 用户说的 | 今天已经在跑的东西 | 出处 |
|---|---|---|
| 整体是一个大集合 | `g_errors[]`，24 个 kind，一张表 | `src/types/error_types.c` |
| 下面分成多个小集合 | `ImErrorDomain`，6 个域 | `src/types/error_types.h` |
| 如 FileError 之类的 | `im_error_domain_name()` 返回逐字 `"FileError"` | `src/types/error_types.c` |
| 处理只需要针对单个小集合 | `im_error_domain_enum(domain)` 把一个域取成一个 `ImEnum` | `src/types/error_types.h` |
| **编译器检测到所有都有处理就能安全过关** | **`--lint` 报 `case try finite err type 'FileError' is missing members: …`** | `src/lint_mod.c` |
| 集合可以并、可以起别名 | `type AppError = FileError` / `type CombinedError = FileError + ParseError` | `vtest/lint_case_try_alias_v04.im` |

★ **语言写法今天就是这样**（`vtest/case_try_v04.im` 逐字）：

```im
type FileError = "not_found", "permission_denied"
ferr = err("not_found")
case try ferr {
    err(e) | e in FileError: say "file-error"
    err(e): say "other-error"
    ok(v): say "bad-ok"
}
```

★ **穷尽性今天就在证** —— 故意只处理一半的 `vtest/lint_case_try_members_v04.im` 跑 `--lint` 的输出逐字：

```
[lint] line 4 [WARN] case try finite err type 'FileError' is missing members: permission_denied, disk_full
```

★ 而**全处理的那条**（`vtest/lint_case_try_alias_v04.im`）**rc=0**。

⇒ ★★ **所以要做的不是「从零建一套」，是「把成员从字符串换成整数码」** —— 而 `im_enum_encode` / `im_enum_decode` / `im_enum_code_limit` / `IM_ENUM_U8` **已经在了，那正是为这件事准备的。**

### §1.4 ★ 今天的两处实况（我实跑，不是读码）

```
try { x = 1 / 0 } catch (e) { say "caught: " + str(e) }
→  caught: division_by_zero

try { throw "my_error" } catch (e) { say "got " + str(e) }
→  got my_error
```

- ★ **`catch (e)` 绑定的是一个纯字符串** —— `str(e)` 得到 `"division_by_zero"`（16 个字符）⇒ **没有 `code`、没有域、没有任何字段。**
- ★ **`throw` 是语言语句**，可以扔任意字符串。
- ★ **未捕获 ⇒ `[exception] uncaught: division_by_zero` + `at ip=N frames=M`，rc=1**；被捕获 ⇒ rc=0。
- ★ **`catch` 变量在编译器里是一个【全局槽】**（不是局部）—— `finally`-only 的 try 还会用一个私有全局 `__inimerse_finally_error` 把异常保住再重抛。
- ★ **全仓唯一碰整数码的地方是 `vm_throw_kind`，而它的两个分支做的是同一件事** ⇒ **码被丢掉，只当布尔用。**

### §1.4 ★ 错误码的载体是【元格式类型】，不是整数（用户裁定，2026-10）

★ **用户逐字**：「**可以用元格式定义错误码，防止与整数混淆**」。

★★ **这一条改的不是码值，是码的【类型】**。本文档 §0 与 §2 描述的那套（一个字节、高半字节域、低半字节成员）**仍然成立** —— 改的是**它在语言里以什么身份出现**：

| | 今天 | 裁定之后 |
|---|---|---|
| 码在语言里的类型 | **没有自己的类型** —— 它只是一个数，或一个字符串名字 | ★ **一个元格式类型**：它声明自己的表示与宽度（**v0.6 的 R3**，见 `docs/PLAN_V06.md` §7 第 12 条） |
| `catch (e)` 绑到的东西 | **纯字符串**（`e` 是消息，**没有 `e.code`** —— 见 §5.1 的 C4） | ★ **一个该类型的值**：取码是取它的一个成员，不是从字符串里解析 |
| 与整数的关系 | ★ **可以互相混淆** —— `e == 1` 在语法上没有任何东西拦着 | ★ **类型不同，所以混淆在编译期就不成立** |

★★★ **为什么这一条值钱（它把一处已知的缺口从「要补一条路径」变成「类型系统的推论」）**：§5.1 的 C4 量出的缺口是 —— **码已经在表里、已能由名字编出来，但语言层没有路径把它取出来**（`catch (e)` 绑的是纯字符串，模式匹配比的也是成员名字符串）。★ **有了元格式类型之后，「取码」不需要新造一条路径：它就是取一个类型成员**，而**「这个码不是那个整数」也不需要一条检查：它们是两个类型。**

★★ **两条边界（照实）**：
① ★ **R3 本身在 v0.6 只做「与元格式重叠的那一半」**（声明表示与宽度 + 编译期校验），其余五件（位段提取、运算符重载、自带加解密、声明式构造、零成本降低）**另立一条线**（`docs/PLAN_V06.md` §7 第 12 条）。⇒ ★ **本条裁定落在 R3 的射程之内；射程之外的部分不在这里。**
② ★ **本文档 §1.2 的第 ① 点（`catch` 怎么声明处理哪个域 = D「保持今天的守卫式不动」）与这一条不冲突**：那一条说的是**怎么声明**，这一条说的是**码是什么**。★ **D 今天仍然有效，除非实现时发现守卫式与类型化取码不相容 —— 若不相容，那是一个新问题，不是这一条的延伸。**

★★ **本条的射程**：★ **本文档其余各节描述的是「码值与域」的设计，它们不因这一条而失效**；★ **受它影响的只有「码在语言里的身份」那一栏** —— ★ **而那一栏今天在各节里没有单独写过，所以本节是补上的，不是改过的。**

## §2 字节布局

**一个字节。高半字节 = 域，低半字节 = 域内成员。`0x00` = ok。**

```
  7 6 5 4 | 3 2 1 0
  ────────┼─────────
    域    |  成员
```

| 域 | 高半字节 | 名字 | 成员数 | 码段（含两端） | 空位 |
|---|---|---|---|---|---|
| **ok** | **0** | —— | —— | **`0x00`** | —— |
| FILE | 1 | `FileError` | 5 | `0x10`–`0x14` | 11 |
| PARSE | 2 | `ParseError` | 2 | `0x20`–`0x21` | 14 |
| ARITHMETIC_VM | 3 | `ArithmeticVMError` | 3 | `0x30`–`0x32` | 13 |
| MEMORY_VM | 4 | `MemoryVMError` | 4 | `0x40`–`0x43` | 12 |
| TYPE_VM | 5 | `TypeVMError` | 3 | `0x50`–`0x52` | 13 |
| RUNTIME_VM | 6 | `RuntimeVMError` | 7 | `0x60`–`0x66` | 9 |
| **保留** | **7–15** | —— | —— | —— | 给未来的域 |

### §2.1 为什么「方便用」

1. **`code >> 4` 就是域** —— 一次移位，不用查表，不用记数字段。
2. **`code & 0x0F` 就是域内成员。**
3. **`code == 0` 就是成功** ⇒ `if e.code != 0` 直接可用，**不需要一个单独的 `is_ok` 谓词**。
4. **十六进制一眼读出**：`0x21` 就是 `ParseError` 的第 1 个（0 起算的第 2 个）。
5. **`switch (code >> 4)` 直接分派到域处理器。**
6. ★ **一个字节 ⇒ 塞得进 `Value` 的一个字节，也正好落在 `IM_ENUM_U8` 上。**
7. ★ **域 0 留给 ok，所以「真错误的域恒非 0」** ⇒ **成员码是 `0xN0` 时不会和 ok 混淆**（`0x10` ≠ `0x00`）。

### §2.2 为什么不留「每域一个泛化错误」槽

★ 我一度想在每个域里留一个「该域的泛化错误」（例如 `0x10`）。**放弃了**，理由是**它会污染穷尽性语义**：如果 `0x10` 表示「FileError 里没分类的那个」，那么「处理了 `0x10`」是否算「覆盖了 `0x11`–`0x14`」？**这个问题没有不武断的答案，而它会变成第二个必须被断言的规则。**

⇒ **每个域 16 个槽全部可用，`0x00` 是唯一的非错误码。**

## §3 四个裁定的落地形状

### §3.1 ① D —— 语法不动，只换表示

★ **今天的守卫式写法原样保留**：

```im
type FileError = 0x10, 0x11, 0x12, 0x13, 0x14
case try ferr {
    err(e) | e in FileError: say "file-error"
    err(e): say "other-error"
    ok(v): say "bad-ok"
}
```

★ **改成整数码之后，`case` 的穷尽性检查一个字都不用改** —— 它检查的是「这个集合的成员是否全部被覆盖」，**与成员是字符串还是整数无关。**

★ **但 `case` 里今天那种「按字面量匹配」的写法要跟着换**：

```im
case try specific {
    err(0x11): say "permission-denied"     // 原来是 err("permission_denied")
    err(e) | e in FileError: say "file-error"
}
```

### §3.2 ★ 名字不能丢 —— 码是运行时的身份，名字是给人看的把手

★★ **状态（`main @ 80ddbfb`）：这一节标题里的那句话是【目标态】，而今天是反的。** 这是 `exact-lumen` 做完 §5 第 6 条之后量出来的（观测点 `e7ffe7c`），它的表逐字是：

| | 今天是什么 | 谁在用它 |
|---|---|---|
| **声明里的成员** | **字符串**（`type FileError = "not_found", …`） | 编译器 / `im_typeset_*` |
| **模式匹配比的字符串** | **字符串**（C4：`lint_mod.c` 里两处 `strcmp(成员名, 成员名)`） | `case try` / `case` 的 `err(...)` 分支 |
| **运行时的码** | **字节 `0x10`–`0x66`**（§5 第 1 条落定、第 6 条接上） | `g_errors[]`、`im_error_domain_enum`、`--lint` 的输出 |

⇒ ★ **一致的是前两样**：声明与匹配**都**是名字，**所以 C4 今天不是缺陷，是自洽的**。★ **落后的是第三样**：码已经在表里、已经能由名字编出来，**但语言层没有任何路径把它取出来** —— `catch (e)` 绑的是纯字符串（§1.4 实跑过），**没有 `e.code`**。
⇒ ★★ **所以今天「名字是运行时的身份，码是给人看的（`--lint` 印它）」—— 而这一节标题说的正好相反。** 标题说的是**目标态**，它没有变；变的只是「今天兑现了多少」。
★ **判据**：★ **设计档里「X 是身份、Y 是把手」这类句子，说的是【目标态】还是【今天】，只有拿今天的两条路径去比才知道 —— 而它读起来两种都像。**

★ **`--lint` 今天报的是名字**（`is missing members: permission_denied, disk_full`）。**换成整数码之后它必须同时给两个**：

```
[lint] line 4 [WARN] case try finite err type 'FileError' is missing members: 0x11 permission_denied, 0x12 disk_full
```

★ **理由**：`0x12` 是运行时和磁盘上的东西，**而读 lint 输出的是人**。**只给码，人要去查表；只给名字，人无法把它对上运行时看到的值。** ⇒ **两个都给，且顺序固定（码在前、名字在后）。**

★★ **而「名字不能丢」这条真正的理由比上面这句硬，是 `noble-zephyr` 实测出来的**（观测点 `5805538`）：

★ **消息字符串不是「给人看的把手」，它是渲染层的输入。** 三处独立的假设都只认 `VAL_STRING`：
- 未捕获时的渲染逐字是 `(err->type == VAL_STRING && err->sval) ? err->sval : "(non-string value)"`（`src/vm/vm.c`）；
- 创建时逐字 `err.type = VAL_STRING; err.sval = (char*)vm_intern(vm, msg); err.ival = 1;`（同文件）；
- 落槽时的 intern 也只认 `VAL_STRING`，并用 `ival != 1` 当「已经 intern 过」的记号（同文件）。

★ **实测**：`throw 42` ⇒ `[exception] uncaught: (non-string value)`；`throw {"code": 7, "msg": "boom"}` ⇒ **同一句**、值整个丢掉。
⇒ ★★ **把消息字符串【换掉】= 让所有非字符串错误在默认输出里变成 `(non-string value)`。** ⇒ **码必须与消息【并存】，不是替代它。**
★ 而 `--err-json` 那条分支走的是 `value_to_string`（它会把 `42` 印出来）⇒ **同一个 `err`、两个分支两种渲染，而只有 plain 那条今天可达**（见 §7 第 8 条）。

### §3.3 ② C —— ★ **更正：这不是两条守卫，是一条**

★ **第一版这里写的是「两条守卫，红在不同的地方」，并列了「一条 CTest」与「`im_enum_create` 按 `IM_ENUM_U8` 拒绝越界」。**
★ **实测之后：第二条不是一条守卫，因为它的前提是假的。** 原话逐字留在上面这段更正里。

**实测（观测点见 §7）：**

| 读数 | 逐字 |
|---|---|
| `src/types/enum.c` 的宽度选择那一行 | `e->width = count <= 256 ? IM_ENUM_U8 : (count <= 65536 ? IM_ENUM_U16 : IM_ENUM_BOXED);`（★ 原写作 `:28`；`exact-lumen` 的第 6 条给 `struct ImEnum` 加了 `codes` 字段 ⇒ 那行今天是 `:29`。按家法改形式、不换号） |
| `src/types/enum_probe.c:35-38` | `/* Width selection is defined by representable member codes. */` + `sizes[] = {256, 257, 65536, 65537}` / `widths[] = {IM_ENUM_U8, IM_ENUM_U16, IM_ENUM_U16, IM_ENUM_BOXED}` + `assert(large && im_enum_width(large) == widths[si]);` |
| `./build/enum_probe` | `enum_probe: ok`，rc=0 |
| 语言侧 17 个成员（`type Big = 0, 1, … 16`） | rc=0，`case v { in Big: … }` 印 `in-big` |

⇒ ★★ **`IM_ENUM_U8` 的意思是「这些码塞得进一个字节」（≤ 256），不是「至多 16」。**
⇒ ★ **而 `enum_probe` 正在断言这一点，而且是绿的** ⇒ **按第一版写第 3 条，必须打破一条绿色断言才能满足它。**

★★ **病因在 §2.1 第 6 条里已经写出了一半**：★ 「一个字节 ⇒ 塞得进 `Value` 的一个字节，也正好落在 `IM_ENUM_U8` 上」—— ★ **「塞得进一个字节」与「塞得进一个半字节」是两件事，而第一版的 §3.3 / §5 第 3 条把后者写成了前者的名字。**

⇒ ★ **结论**：★ **半字节的约束在枚举层【之上】，它是错误表这条链的性质** ——
★ **而那正是 §5 第 2 条那个域守卫读的东西。** ⇒ **守卫只有一条，第 3 条撤掉。**

★ **而这条「不可能」有一个机械原因**：`im_enum_create` 的签名逐字是 `ImEnum *im_enum_create(const char *type_name, const char *const *members, size_t count);`（`src/types/enum.h`）—— ★ **它没有宽度参数**，宽度是 `src/types/enum.c` 自己算出来的 ⇒ **「按 `IM_ENUM_U8` 拒绝」今天不可能发生，除非先给这个签名加一个宽度参数。**
★ 而那是**一处签名变更**，它属于「待批准的变更」，不属于 §1.2 的裁定表 —— ★ **一条被写进裁定表的前提，如果它今天还不具备，那它不是前提，是一个愿望。**

★★ **并且：「每域 ≤ 16」是「高半字节点名本域」的【推论】，不是一条独立事实。**
★ 理由：**一个域只有 16 个低半字节槽，所以第 17 个成员必然带一个不再是本域的高半字节。**
★ 实测：给 RUNTIME_VM 加 10 个成员 ⇒ rc=1 且点名 `IM_ERROR_DOMAIN_RUNTIME_VM holds 17`，**而高半字节那条问题跟着红** ⇒ **造不出「每域 ≤ 16」单独红的对照。**

⇒ ★ **判据**：★ **当两条守卫里的一条是另一条的推论时，「它们红在不同的地方」这句话是假的 —— 而它在纸上看不出来，只有当你试着让它们各自单独红的时候才知道。**

### §3.4 ③ 不留旧码

★ **表里不设 `legacy_code` 一栏。**

★ 依据：**全仓唯一读整数码的地方是 `vm_throw_kind`，而它把码丢掉** ⇒ **今天换码零代价**；★ **留一栏就多一处会过期的东西**，而这一族里「一个没有门禁守着的数字」已经出现过多次。

★ **代价要说准**：★ **如果仓库外的什么东西记过 1001–2307，它今天没有任何办法核对** —— 而**这个风险是「不知道」，不是「已知无害」。**

## §4 速查途径

### §4.1 形状：`inimerse errors`（子命令，不是旗标）

★ **与现有子命令同形**（`where` / `capabilities` / `changelog` / `symbols` / `bytecode` 都是单词子命令），**不用 `--` 旗标**。

| 命令 | 输出 |
|---|---|
| `inimerse errors` | **整张表**，按域分组：域名 · 高半字节 · 每个成员的 `0xNN` + 名字 |
| `inimerse errors FileError` | **只一个域**（域名、或 `1`、或 `0x1`） |
| `inimerse errors 0x21` | **反查**：`0x21  ParseError  invalid_format` |
| `inimerse errors --json` | 机器可读（与 `--err-json` 同族，那个旗标今天已经在 `src/main.c`） |

★ 输出里**必须同时有码和名字**（同 §3.2），**并且必须自报它读的是哪张表**（`24 kinds / 6 domains, 16 slots per domain`）。

### §4.2 ★ 这张表必须是【派生的】，不是第二份抄本

★ **`inimerse errors` 的输出必须从 `g_errors[]` 派生。** ★ **判据是一条能红的断言**：**给 `g_errors[]` 加一个成员 ⇒ `inimerse errors` 的输出必须跟着变**（数一下行数/成员数）；**改一个码 ⇒ 输出里那一行必须跟着变**。

★ 理由：★ **这个仓库里「同一件事有两份抄本」已经反复出现**（`im_typeset_*` 与 VM 的 `vm_set_*` 是两个互不相识的集合实现；`[obs:` 是一张自己给自己发的免票）。**第二份抄本与第一份在输出里长得一样，直到它们不一致的那一天。**

### §4.3 ★ 反查必须能回答「这个码在哪个域」

★ `inimerse errors 0x21` 给出的不只是名字，**还有域和它在域内的序号** ⇒ **这就是「方便用」的可执行形式**：拿到一个运行时看到的数字，**一条命令就能把它变成人话。**

## §5 要改什么（接线清单）

★ **按依赖顺序，每一条都要能单独验证。**

| # | 改什么 | 判据（能红） |
|---|---|---|
| **1** | `g_errors[]` 的整数码换成 §2 的字节 | 24 个码逐条对上 §2 的表；**旧值一个都不在** |
| **2** | **每个域 ≤ 16** 的 CTest | 临时给某域加第 17 个成员 ⇒ **rc=1 且点名是哪个域**；还原 ⇒ rc=0 |
| **3** | **错误值带上 `code`**（今天只有字符串） | `catch (e)` 之后 `e.code` 能读出那个字节；**未抛时不存在这个值** |
| **4** | **`--lint` 的缺失成员名单同时给码与名字** | 故意漏一个 ⇒ 输出里**既有 `0xNN` 也有名字**，且**顺序固定** |
| **5** | **`inimerse errors`**（四个形状） | 输出与 `g_errors[]` 派生一致；**加一个成员 ⇒ 输出跟着变** |
| **6** | **`im_enum_encode` / `im_enum_decode` 接上 `im_error_domain_enum`** | 域成员的名字 ⇄ 码 双向可逆，**逐条对 24 个成员** |

★ **顺序的理由**：**1–2 是「表的形状」，3–6 是「表被谁读」。** ★ **先立形状再接线** —— 否则接线会以「它今天跑得通」为由把形状固定成一个临时的样子。

### §5.1 ★★ 第 3 条的射程比它看起来大：四个消费面，而第四个是语言面

★ `noble-zephyr` 数出**四个**拿到错误值的地方，不是一个：

| # | 形状 | 今天拿到什么 | 码要活到这里需要什么 |
|---|---|---|---|
| **C1** | `catch (e)` 带变量 | 槽里是**完整 32 字节 `Value`**，类型端到端保持（实测：dict 穿 `finally` 重抛后 `e["code"]` = 7） | 只要 `Value` 有码字段，**机制不用动** |
| **C2** | `catch { }` 不带变量 | `varIdx = -1` + `ignore = 0` ⇒ 两个分支都不进、**值一个字不留** | **按设计**，但码也一起没了 |
| **C3** | 裸 `try`（无 catch） | 走 `value_to_string` ⇒ **类型被压成字符串**，落进 `last_ignored_exc`（**`char *` 不是 `Value`**） | ★ 码到这里已经没了，且落点是 `char*` ⇒ 想留必须改字段类型 |
| **C4** | ★★ `case try e { err(...) }` | 走 `OP_CALL_BUILTIN` + 名字上的三个内建（`is_ok` / `result_error` / `result_value`），再就地用 `OP_EQ` 与 `OP_INDEX_GET` 比 payload | ★★ **见下** |

★★ **C4 是最容易被忘的那个，而它把这件事从「运行时改动」变成「语言改动」**：`err(...)` 的模式**能匹配结构化 payload** —— `vtest/case_try_v04.im` 里逐字有 `err({"kind": "not_found", "code": 404})`、`err({"outer": {"inner": {"code": 404}}})`、`err([first, {"code": code}])`、`err(e) | e in FileError`。

★★ **判据**：★ **payload 换成整数码 ⇒ 每一条 `err("not_found")` / `err({...})` / `err([...])` 模式都静默不匹配 —— 不报错，只是没有分支命中。**

★ 加上声明形式本身（`type FileError = "not_found", "permission_denied"` —— **成员是字符串字面量**）⇒ ★ **裁定 ① 的「成员」有两处用法：它怎么写、以及它怎么被比。** ⇒ **两处必须同批改，否则 C4 会以「没有分支命中」的样子失败。**

### §5.2 ★★ 「让每一个抛出点都有码可接」比「把码接上去」大得多

★ 32 个 `vm_throw_kind` 调用点**全是裸字符串字面量**；而**外部 20 个 `vm_throw_msg` 调用点里，15 个是自由英文句子、5 个连字面量都不是**（`snprintf` 现拼）⇒ ★ **这 20 处不在 `g_errors[]` 的 24 个 kind 里。**
⇒ ★ **它们要么各自映射到一个 kind，要么永远没有码。** ★ **第一版把这件事说成了「24 个码换个形状」，而实际是「32 + 20 个抛出点各自决定有没有码」。**

## §7 诚实边界

★ **第 8 条是这一节里唯一一条「不是本档的边界、而是一个独立的缺陷」的，它由 `noble-zephyr` 实测发现、我单独登记。**

1. ★ **「今天换码零代价」是我量过的**（唯一消费者把码丢掉），**但「仓库外没有人记过旧码」我量不到。**
2. ★ **「每域 ≤ 16」这条约束今天没有守卫** —— 今天最大一域是 RUNTIME_VM 的 **7**，**离上限还有一半**，**而「今天够用」不是「将来够用」。**
3. ★★ **第一版这里写「`im_enum_create` 按 `IM_ENUM_U8` 拒绝越界这件事我没实测过」。实测的结果是：那条设计今天为假** —— `IM_ENUM_U8` 是「塞得进一个字节」（≤ 256），不是「至多 16」，而 `enum_probe` 断言前者且是绿的。★ **§5 第 3 条已撤，见 §3.3 的更正。** ★ **这一条的教训：一条「我没实测过」的边界，写的往往是「我以为是那样」。**
4. ★ **`inimerse errors` 的四个形状是我提的，用户只说了「可以输出对应码、域」** —— **形状待确认**；`--json` 那个尤其。
5. ★ **「编译器检测到所有都有处理就能安全过关」今天成立的范围**：★ **只在 `--lint` 下成立，不在默认编译路径下成立。** ★ **`inimerse foo.im` 不会因为一个 `case` 没覆盖全而拒绝编译** —— **这是「安全过关」这句话的射程边界，不能读宽。**
6. ★ **本文档没有实测任何一条** —— 它是设计。★ **§5 的六条判据全部是「应当能红」，不是「已经红了」。**
7. ★ **§3.3 的更正块里那四条读数是实测的，观测点写在各条旁边**；★ **它证伪的是本档第一版的一条设计，不是引擎的一条行为。**
8. ★★★ **`--err-json` 从初始提交起就 100% 不可达 —— 这是本档范围外的一个独立缺陷，`noble-zephyr` 实测发现，我单独登记。**

**机制（一行）**：`src/main.c` 里 `--err-json` 是一个**独立 `if`**（设标志），紧接着是**另一条** `if/else if/…/else break` 链，**链里没有它** ⇒ `else break` 直接跳出 ⇒ **token 不被 shift 掉** ⇒ `argv[1]` 仍是 `--err-json`，**而 `argv[1]` 就是脚本路径槽** ⇒ ★ **`g_err_json` 唯一的取值方式，同时把脚本路径设成了 `"--err-json"`。**

**实测（观测点 `5805538`，`build/inimerse`）**：

| argv | 结果 |
|---|---|
| `--err-json` | `{"error":"io","detail":"--err-json","fix":"check that the script path exists"}`，**rc=1** |
| `--safe --err-json --time-limit 10 <file>`（**= `tools/ai_run.ps1` 与 `tools/mcp_server.js` 逐字产出的 argv**） | **同一条 io JSON**、rc=1、★ **脚本体一个字都没跑** |
| `<file> --err-json` | 脚本跑了，但错误是**朴素格式**（那条循环只看 `argv[1]`） |
| `--err-json --params /nonexistent <file>` | **仍是那条 io JSON** ⇒ 今天唯一可达的 JSON 行是 `main_err_json` 那条 |

★ **`git blame` 指到初始提交 `8248e08`（`Release Infiverse 0.2.0`）** ⇒ ★ **不是回归，从第一天就是这样，而 `tools/` 里的两个消费者也是同一天写的。**

★★★ **而正确的形状就在同一个文件、往前两个 block 的地方**：注释逐字 *"Scanned rather than matched at argv[1] so the option works in any position"*，而 `--params` 与 `--time-limit` **都全位置扫描并把 token shift 掉** ⇒ ★ **`--err-json` 是 `src/main.c` 里唯一「只认 `argv[1]`、且不消耗」的旗标** —— ★ **而它头上的注释逐字写着 *"repeatable and order-independent (--safe / --err-json)"***。

★★ **判据**：★ **注释断言的那个性质，代码没有。** ★ 而这比一般的「注释与代码不符」更重：★ **正确的形状就在同一个文件里，它不是没人想过，是这一处没照做。**

★ **为什么单独登记**：★ **它不是 error 码的一部分，它先于码存在**；★ **而它是唯一一条「工具链消费者今天 100% 跑不了」的** —— `--err-json` 是 `tools/ai_run.ps1` 与 `tools/mcp_server.js` 取结构化错误的唯一途径。

★ **三个生产者、三种键集**（读码；只有 `io` 那条是实测）：`parse` = `{"error","line","col","expect","got","fix"}`；`io` = `{"error","detail","fix"}` ← 实测；`exception` = `{"error","message","ip","frames"}`。★ 而 `tools/README.md` **只文档化了第一种的形状**并把三个 kind 名并列在同一行 ⇒ ★ **文档描述的是三个里的一个。**

★ **红对照（今天必失败）**：`./build/inimerse --safe --err-json --time-limit 10 <file>` 必须 (a) 印出脚本体自己的 stdout、(b) 印出一行 JSON —— **今天两者都没有。**
