# Infiverse update 2026-08-14 (infinite-set intervals + comprehension polish)

## 1. Infinite-set interval literals (R = reals)
- (,)        = real number set R (whole real axis)
- (,a) / (,a] = (-inf, a) / (-inf, a]
- (a,) / [a,) = (a, +inf) / [a, +inf)
- (a,b) / (a,b] / [a,b) / [0~1] : open/closed intervals (math notation)
- separators: ',' or '~' inside '(' form; '[' form requires '~'
  (because [a,b] stays a list literal; [a,) still works as interval)
- endpoints may be any expression (variables allowed): (,a) (a,) (2*x,10)
- representation: SetObj kind=2 with new builtin index 24 = "R"
  - (,) = nameIdx 24, lo=-1e308, hi=+1e308, open
  - x in (,) is true for any number
- VM: builtin_set_name[24]="R", builtin_set_index("R")=24,
  builtin_contains(24)=any number, builtin_subset: everything subset of R,
  R subset of nothing but itself
- list((0,1)) -> nil (real intervals not enumerable); min/max of R intervals -> nil
- Z(,5] / Z(,5) / Z(,) now also parse (empty endpoint forms on builtin sets)
- parser: looks_like_bare_interval + parse_bare_interval hooked into parse_primary
  before '(' / '['; bare-interval detection scans for top-level ',' or '~'
  (nested depth respected); [a,b] stays list, [a~b]/[a,) interval

## 2. Set comprehension polish
- existing {x in S | cond} skeleton completed:
  - infinite source (list returns nil) now THROWS
    "comprehension: source set is not enumerable" instead of silently nil
    (catchable with try/catch)
  - removed [dbg-add] debug print from L_SET_ADD

## 3. Fixes
- vm_set_to_array: integer builtin intervals (N/Z/Z+/Z-) enumerate VAL_INT
  (was VAL_FLOAT) so comprehension results equal integer set literals
  ({x in Z[1~10] | x%2==0} == 2,4,6,8,10 now true)
- set_subset: unbounded endpoints (+-1e308) no longer break subset checks
  (N in (,) / Z in (,) / Z+ in (,) now true)
- set_equal: kind0 set with exactly one component == kind2 interval
  ((0,2)*(1,3) == (1,2) now true)
- looks_like_interval: removed over-broad comma rule that misread
  size(1,2,3) as an interval (builtin-set + '(' already handled by name check)

## 4. CRITICAL build fix (debug_mod.dll)
- freshly-built engines (any source, incl. 13日备份) crashed at 0x3623fc
  while loading mods/debug/debug_mod.dll (built 2026-08-11)
- root cause: the OLD dll imports from "inimerse.exe"; when a NEW engine
  process (different exe name / different export layout) loads it, the loader
  re-loads the inimerse.exe file and resolves against it, producing a bad
  target -> 0xC0000005
- fix: rebuilt debug_mod.dll from mods/debug/debug_mod.c linked against the
  current inimerse.lib (imports "inimerse.exe" matching the deployed engine)
- old dll kept as mods/debug/debug_mod_old_20260811.dll
- NOTE for future builds: whenever the engine binary is rebuilt, rebuild
  debug_mod.dll the same way if the engine exe name/export set changes
