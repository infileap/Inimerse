渐进教程

从「打印一行字」到「编译一个模块」，每一步都可以在这台机器上原样跑一遍。 这一页上的每一段输出都不是写上去的：它是生成器真跑一遍引擎之后记下来的。

每一步都必须能在本地跑通，而且必须真的演示它说要演示的那件事。 这是两个判据，不是同一个。一个只检查「命令跑通了」的生成器，对一个什么都没演示的步骤 永远是绿的 —— 本页底部的两条探针就是在生成器印出两笔一模一样的读数之后补上的。

这份记录是什么

从头开始

每一步都印出四样东西：命令、在哪儿跑、stdout、stderr。空的也印 —— 「（空）」是一个零， 一个被省略的零与一个真的零在页面上长得一样，而它们不是一回事。

这两条探针

教程的价值不在「十四步都跑通了」，而在**十四步各自演示了不同的东西**。所以生成器里 有两条关于它自己的探针。

你自己跑一遍

下面两行就是这份记录的生成过程。第二条会把 data/tutorial.js 整个重写。

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j"$(nproc)"
node website/scratch/run_tutorial.js

★ 注意 -S 后面那个 .：cmake -B 只决定**产物放哪**， 源树由 -S 定。把 -B 指到别处而 -S 留在原地， 会安静地编译另一棵树 —— 而结果看上去完全正常。

这一页没测过什么

没有真浏览器。 本机没装浏览器自动化工具，所以「这一页显示 X」的准确含义是「DOM stub 把 X 渲染进了它的 DOM」。 stub 与真浏览器之间的差距没有被测过 —— 版式、换行、滚动都可能有出入。 这句话留在这里而不是删掉：它是一个**已知的未测面**，不是一个已经解决的问题。
