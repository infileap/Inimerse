## 第一节 ★★★ 头条一：那 59 处的三个口径必然同判 —— 那是一个恒等式，不是一条读数

| 口径 | 对象 = B（59） | 对象 = A（137） |
|---|---|---|
| ① 不认引号 | **59** | **137** |
| ② 认单引号与双引号 | **59** | **59** |
| ③ 双引号里的 `$`／反引号仍算展开 | **59** | **61** |

★★★ **B 的定义就是「① 命中【且】② 命中」**，而 **③ ⊇ ② 成立**（本件量到 **0 处**反例）⇒ 在 B 上，三个口径**必然同判**。
⇒ **问「B 在三个口径下变成几」，答案只能有一个：`|B|`。** 它在【选对象的那一刻】就被定死了，与测量无关。
⇒ ★★★ 判据：**一个口径的效果如果全部落在【上一个口径不收】的地方，那么在一个由【上一个口径收了】定义的对象上量它，得到的那个数不是「它没效果」，是【对象与它的作用域不相交】。**

### 真读数在 A 上：**137 / 59 / 61**

★★ **② 与 ③ 的差 = 2 处** —— 逐字：

## 第三节 ★★★ 头条三：「关于命令的期望」**可以**与「命令」分开 —— 但要用形状判据，不是语义判据

派件要求「给数，并给一条可判的判据」。

### 候选判据一（语义）：❌ 不可判

> 「一条反引号里的文本，若不含任何可执行名、也不含任何 shell 元字符，它就不能是一条命令」

| 方向 | 命中 |
|---|---|
| 方向 1（无头名 ⇒ 不是命令） | **0 / 59** |
| 方向 2（有头名 ⇒ 是命令） | **59 / 59** |

★ **两个方向都没有分辨力**：59 处**全部**有可执行名。反向反例（**有可执行名、却是关于命令的期望**）**5 处**，逐字：

```
docs/STATUS.md:1096                     cmd=`ctest (expect 97/97, 0 skipped)`
docs/STATUS.md:2576                     cmd=`ctest (expect 108/108, 0 skipped)`
docs/STATUS.md:2654                     cmd=`ctest (expect 108/108, 0 skipped)`
docs/streams/json-min-nul-escape.md:178 cmd=`ctest (expect 92/92)`
docs/streams/vverse-cli.md:74           cmd=`ctest (expect N/N)`
```

⇒ **含可执行名 ≠ 是一条会跑的命令。**

### 候选判据二（形状）：✅ 可判

> **「第二个 token 以 `(` 开头」**

| | 数 |
|---|---|
| 在 B（59）上命中 | **5** |
| 在全部 255 处上命中 | **5** |
| 假阳性（形状命中但不含 `expect`） | **0** |

★★ **它只读形状、不读语义**（判据 Q4.1），**在 255 处上命中的 5 处全部在 B 里**，**假阳性 0**。
⇒ ★★★ 判据：**「关于命令的期望」与「命令」是可以分开的 —— 但分开它们的不是「它是不是一条命令」这个语义问题，而是「它的第二个 token 是不是一个括号」这个形状问题。一个语义问题判不了，换一个形状问题往往判得了。**

## 第四节 四档

### 派件的四档（对象 = B = 59）

| 档 | 处数 |
|---|---|
| ① 三个口径同判 | **59** |
| ② 只有第三个口径改判 | **0** |
| ③ 三个口径都不收 | **0** |
| ④ 判不出 | **0** |
| | **和 59 ✓** |

★ ② = 0 是**恒等式**（见第一节），不是「没有这样的处」。

### ★★★ 同一个四档用在 A（137）上：① 59 ／ ② 0 ／ ③ 0 ／ ④ **78**

★★★ **那个 ④ = 78 不是「判不出」—— 是那个四档划分漏了一格。**
三个布尔值**枚举**出来（不是从链条推）：

| (①,②,③) | B 上 | A 上 | 是什么 |
|---|---|---|---|
| (F,F,F) | 0 | 0 | 三个都不收 |
| (F,F,T) | 0 | 0 | — |
| (F,T,F) | 0 | 0 | — |
| (F,T,T) | 0 | 0 | — |
| **(T,F,F)** | 0 | **76** | ★ 只有 ① 收：**引号里的字面量** |
| **(T,F,T)** | 0 | **2** | ★ ①③ 收、② 不收：**双引号里的 `$`** |
| (T,T,F) | 0 | 0 | 不可能（③ ⊇ ②） |
| (T,T,T) | **59** | **59** | 三个都收 |

★★★ **派件那个四档把 (T,F,F) 那一格 —— 「元字符在引号里，是字面量」—— 放进了 ④「判不出」。** 而它恰恰是**最大的一格（76 处，加 (T,F,T) 的 2 处 = ④ 报的 78）**。
⇒ ★★★ 判据：**一个四档划分如果只按【第几把收】写，就会把「① 收了、②③ 没收」这一格挤进「判不出」。**
★ 与 **壬⁶** 那条同族：**一个划分的定义域漏了一格，而落进那一格的那一处恰好是刚刚被救回来的那一个。**

### ★★★ 而本件自己也漏了一格

★ 本件最初**从链条 `① ⊇ ③ ⊇ ②` 推**出 4 格 = `FFF/TFF/TTF/TTT` ⇒ 那 4 格之和 = **135**，而 `|A| = 137` ⇒ **少 2 处**。
★★ 而那 4 格里有**一格是空的**：`TTF`（①②收、③不收）在 `③ ⊇ ②` 之下**不可能存在**。
★★★ **真实的第 4 格是 `TFT` —— 我把它写成了 `TTF`，于是真正有东西的那一格，在我列的清单里不存在。**
⇒ ★★★ 判据：**一个划分的成员，如果是从【一条链】推出来的而不是【枚举】出来的，那么写错的那一个成员，恰好是那条链所禁止的那一格 —— 而真正装着东西的那一格，会在清单里不存在。**

★ 顺带量到：**③ ⊇ ② 成立**（② 命中而 ③ 不命中的 = **0** 处）⇒ **口径 ③ 确实是口径 ② 的加宽**。
★ 本件一开始写的成因（「反斜杠处理不同」）**是错的** —— 那 2 处的成因就是口径本身：**② 认引号 ⇒ 双引号里的 `$` 不算；③ 的规则第 4 条 ⇒ 算。**
