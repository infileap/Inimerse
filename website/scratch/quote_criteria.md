## 第零节 对象与分母

**Q0.1** 本件的对象，取自 [otter-letter 160] 派件逐字：「对象 = 那 59 处（③ 档）」。
★ **但那句话把两个不同的集合当成了一个**：
- 戊⁷ 的**五档**里，**③ = 「根本不是命令」= 54 处**；
- 戊⁷ 报的**那 59 处** = 「R1 在**不认引号**下命中、且在**认引号**下**仍然**命中」= 59 处。
⇒ **54 与 59 不是同一个集合，也不是同一个数的两种写法。** 本件**先给出两者的交、并、差**，再按**59** 为对象往下走（因为派件后面每一个问题都只能问在 59 上：那 6 处「两者都无」是 59 的分桶）。

**Q0.2** 载体 = 全仓受跟踪 `.md`（`git ls-files -z -- '*.md'`）。
**Q0.3** 分母一律**承戊⁷ 的定义**（带命令的处 `B` ／ ⑤ 我的射程之外）。本件**不重定义分母** —— 一条按引号判定的规则，改的应当是**分子**，不是分母。
★ **例外且必须写明**：本件要报的三个口径会改 **R1** 那一格，而 **R1 同时参与分母的定义**（戊⁷ 的 `cmds` 过滤器用了 `rulesHit(s,'naive')`）。
⇒ **三个口径一律只用在【分子】上**（那 59 处各自的 R1 判定），**分母一律用不认引号那一版**。
**Q0.4** 若某口径同时动了分母与分子，**两个数并排印，不许合**。

## 第一节 三个口径的定义（这是本件的核心，逐字写下）

**口径 ①「不认引号」** = `SHELL_META_NAIVE = /[;&|<>$()`\n\\]/`
　　逐字：任何一个位置上的这些字符都算元字符，无论它在不在引号里。
　　它的问题：`grep -c 'add_test(' CMakeLists.txt` 的 `(` 在**单引号里**，是字面量。

**口径 ②「认单引号与双引号」** = `metaOutsideQuotes`（戊⁷ 那一版）
　　逐字：进引号之后，**直到同类引号结束之前**，一个元字符都不算。
　　它的问题：**它把单引号与双引号当成同一种引号。**
　　⇒ 在 shell 里，**双引号里的 `$`、反引号、`\` 仍然会展开**；单引号里**什么都不会展开**。
　　逐字反例：`git -C "$REPO_ROOT" diff --name-only "$range"` —— 认引号后 `$` 不再命中，而**它真的会展开**。

**口径 ③「认单引号、双引号，且双引号里的 `$` 与反引号仍算展开」**
　　逐字规则（本件用它）：
　　1. 逐字符扫描，维护「当前在不在引号里、在哪种引号里」；
　　2. **引号外**：`;&|<>$()` 反引号 换行 `\` 命中；
　　3. **单引号内**：**一律不命中**（shell 里单引号内没有任何展开）；
　　4. **双引号内**：`$`、反引号、`\` 命中；`;&|<>()` **不命中**（它们不是 shell 的展开字符）；
　　5. `\` 在引号外与双引号内转义下一个字符。

★ **三个口径的差别只在两处**：(a) 引号内的字符算不算；(b) **双引号里的 `$`／反引号算不算**。
★ **口径 ② 与口径 ③ 的差**，就是「单引号与双引号是不是同一种引号」这一个问题。

## 第二节 怎么判一条命令「有没有元字符」

**Q2.1** 判定函数返回**命中的那一个字符**（不是一个布尔），因为**是哪一个字符**决定了它在哪个口径下翻转。
**Q2.2** 一条命令在某个口径下「被 R1 命中」= 该口径的函数返回非空。
**Q2.3** ★ 判「这条规则命中了吗」一律**按规则的键 `R1`**，不按它的**描述字符串**（判据 F15，戊⁷ 已立）。

## 第三节 四档

**Q3.1** 对象 = 那 59 处。四档互斥且完备，**和 = 59 ✓**：
- **① 三个口径同判**（三种口径下 R1 的命中与否完全相同）
- **② 只有第三个口径改判**（①②同、③不同）
- **③ 三个口径都不收**（三种口径下 R1 都不命中）
- **④ 判不出**（带理由）
**Q3.2** 「三个口径都不收」**必须与「它是我的定义域造成的 0」区分**（戊⁷ 判据 F5.3）：如果这一档非空，要逐处说它是**对象的性质**还是**我的扫描器的性质**。
**Q3.3** 一个档为 0 时，**照实报 0**，不换定义域。

## 第四节 「关于命令的期望」能不能与「命令」分开

**Q4.1** 这是一个**要回答「能不能」的问题**，不是「我认为应该怎么分」。
　　⇒ 判据：**如果一条判据必须逐处读文本才能应用，那它就不是一条可复核的判据，它是一次阅读。**
**Q4.2** 本件必须给出**数**（今天有几处落在这一格）**和一条可判的判据**；判据若只是「读一遍就知道」，**照实说它只是一次阅读**。
**Q4.3** 一个候选的可判形状（要量它能不能用，不是假设它能用）：
　　一条反引号里的文本，**如果不含任何可执行名，也不含任何 shell 元字符**，它就不能是一条命令。
　　★ 但这条判据的**反向**不成立：含可执行名不等于它是一条**会跑的**命令（`ctest (expect 97/97)` 里有 `ctest`）。
　　⇒ **必须把这条判据的两个方向的命中数都印出来**。

## 第五节 对照

**Q5.1** 两个**反方向**对照：
- **(a) 一处已知「元字符在引号外」**：必须**三个口径都命中**。
- **(b) 一处已知「元字符在引号里」**：必须**口径 ① 命中、②③ 不命中**。
**Q5.2** 若某个对照**红了**（该动的不动、该不动的不动），**照实报红**，不换对照。
**Q5.3** 每个对照必须**逐字印出那条命令**与**三个口径各自的返回值**。
