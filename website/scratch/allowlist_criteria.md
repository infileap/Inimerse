# 戊⁷ 判据：把「⑤ 我的射程之外」做成一份可复核的允许表

**本文件是判据，不是读数。** 它只定义**怎么量**、**量什么**、**什么是量不了**。
所有数都在 `allowlist_reading.md`（本文件的**后代**提交，用 `git merge-base --is-ancestor` 证，不眼看）。

---

## 第零节 载体

**载体** = 全仓受跟踪的 `.md` 文件，由

```
git -c core.quotepath=false ls-files -z -- '*.md'
```

枚举。**不数工作树里未被跟踪的、也不数被忽略的** —— 第五档（只在磁盘上、从不进任何索引）在本件里**单独印**。

---

## 第零节之二 本件的定义域

本件量的**不是**「有多少个数是错的」，而是：

> **那 239 处【本探针不许自己跑】的处里，有多少处是【我真的够不着】，有多少处是【我的允许表自己造的】。**

★ 之所以要问这一句：`③ = 0` 那个 0 有两个来源 —— **文档里真的没有「命令 ⇒ 数」**，
或者 **我的提取器把「命令 ⇒ 数」的候选整个排除在射程之外**。两者在输出里同形。
（这条是 [otter-letter 153] 裁定二的要求。）

## F0 载体与分母，先报

**F0** 先报**载体数**与**分母**，**再报**任何分子。

**F0.1** 分母一律**承丁⁷ 的定义**（那一版 `SHELL_META` 不认引号），**不因本件改了规则而改**。
理由见 F8。

**F0.2** 若本件的分母与丁⁷ 报的数不同，**先说差多少、再说差在哪** ——
**不许**把差压回丁⁷ 的数，也**不许**悄悄换分母。

**F0.3** 分母的定义域是**文件集**，而文件集会因为**上一件的产物落地**而变大。
⇒ **两次测量之间落地的任何产物，都会进入下一次测量的分母。**
这一条必须写出来，因为它是**测量顺序**的性质，不是语料的性质。

## F1 允许表逐条，分开印

**F1.1** 五条规则（R1 含 shell 元字符 ／ R2 可执行名不在允许表 ／ R3 `git` 后面没有子命令 ／
R4 `git` 子命令非只读 ／ R5 本探针不跑这一族）**逐条印出各自挡下的处数**。

**F1.2** ★ **一条命令可以同时命中多条** ⇒ 逐条数**有重叠**，其和**可以大于**分母。
⇒ 另印一份**按【首次命中】划分**的，它**互斥**，**和必须等于分母**。
**两个数都印**，并且**明写哪一个是互斥的那一个**。

**F1.3** ★ 互斥那一份的**和必须与分母对账**，且**对账的对象必须是分母本身，不是一个写死的字面量**。
（一次「和 = 分母 ✓」如果比的是写死的数，那它在分母变了之后仍然印 ✓ —— 那不是对账，是同义反复。）

## F2 代理量 ≠ 真跑

**F2.1** 本探针**不跑**任何被允许表挡下的命令。**允许表的存在就是让「真的跑得动」不可测。**
⇒ 凡报「跑得动」，必须写明**这是代理量**（可执行名能不能解析、`git` 有没有那个子命令）。

**F2.2** 代理量的**反例必须逐处印**：解析不到的可执行名，**逐处**印出它是什么。

**F2.3** 代理量里若含**会改工作树**的 `git`，**单独印**，并写明：
**它代理上跑得动，但跑了就违反本件「一个受跟踪文件都不改」的边界。**
⇒ 「跑得动」与「我许它跑」是**两件事**。

## F3 五档，和 = 分母

**F3.1** 五档：

| 档 | 内容 |
|---|---|
| ① | **对象的性质** —— 那个可执行名／那个 `git` 子命令**不存在** |
| ② | **允许表的性质** —— 跑得动，但**我不许**（会改工作树） |
| ③ | **提取器的性质** —— 那段反引号里**根本不是一条命令** |
| ④ | **判不出**（带理由） |
| ⑤ | **我的射程之外** —— 本件的允许表根本没有把它当成一个候选 |

**F3.2** ★ 五档**互斥且完备**，**和 = 分母 ✓**，且**对账对象是分母**（见 F1.3）。

**F3.3** ★★ **⑤ 必须与 ③ 并排印。**
`③ = 0` 若不与 ⑤ 并排，读起来像「文档里没有那种形状」，而真相可能是「我的射程够不着」。

## F4 ④ 不是垃圾桶

**F4.1** 「判不出」**只在两种情形下合法**：**尺子看不见那种形状** ／ **对象在定义域之外**。
其余每一处「判不出」都是**【我没有去读它】**。

**F4.2** ④ 内部**至少分成三个数**并排：**④a-i 我读了、判得出而没判** ／ **④a-ii 我够不着（射程）** ／ **④b 我根本没去读**。
⇒ 「未做」**不是**「判不出」；把它写成 ④ 是**让一次选择看起来像一次测量**。

## F5 三个对照，且空集要照实报

**F5.1** **该落 ① 的**（一个可执行名不存在）⇒ 落在 ① ✓。
**F5.2** **该落 ② 的**（一个会改工作树的 `git`）⇒ 落在 ② ✓。
**F5.3** **空集对照**：把允许表整张清空 ⇒ **分母会变**。
★ 若清空后**空集**，**照实报红**，并**逐字写出那个空集为什么是空集** ——
**不许**为了让它红而换一个定义域。

**F5.4** ★ 空集对照印出的数，若**恰好等于并集总数**，**先怀疑谓词写反了**。

## F6 边界

**F6.1** **只量不写**：本件**不修改任何一个已有文件的一个字节**。
产物只有**新文件**；`git status --porcelain` 在**跑前跑后**各印一次。

**F6.2** 本探针**自己会往仓库里写东西**（一份 JSON 到 gitignored 的 `.build/`）。
⇒ **不许用 `git add -A`** —— 那会把探针的副产物当成产物提交上去。

## F7 ★★★ 元字符只有在【引号外面】才有意义

**F7.1** `SHELL_META` 那个正则在**整个命令字符串**上跑，而 **shell 元字符只有在引号外面才是元字符**。

逐字例子：

```
grep -c 'add_test(' CMakeLists.txt
sed -n 's/^  DIVERGE *\([0-9]*\)$/\1/p'
```

`(` 在**单引号里** —— 它是一个**字面量**，不是一次**子 shell 展开**；
`\` 在**单引号里** —— 它是 **sed 的一个转义**，不是一次**续行**。

**F7.2** ⇒ 一条**按「字符在不在字符串里」判定的规则，不知道引号** ——
于是它把**正则里的 `(`** 与 **sed 里的 `\`** 数成了 **shell 展开**。

**F7.3** ★ 本件必须**两个口径都印**：**认引号**与**不认引号**，以及**两者的差**，
并且**逐处印出被认引号放行的那一批**。

**F7.4** ★ 这与本项目里已发生过的**同一族**（一个**词法状态机被它不认识的某种字面量拖着走**，
方向是**静默少算**、而输出**保持自洽**）是**同族**。

## F8 ★★★ 分母的定义与 R1 那条规则【共用同一个函数】

**F8.1** 本件为修 R1 的误报而改的那个函数，**同时是【分母】的定义的一部分**。
⇒ **一次「修正一条规则」会同时动【分母】与【分子】**，而两个动在报告里**看起来是一个动**。

**F8.2** ⇒ **分母一律用丁⁷ 那一版（不认引号）**；
**认引号的新口径只用在【⑤ 内部的再分类】上**。

**F8.3** ★ 一般形式（本件要求写进判据）：
**一条规则同时决定「谁进来」与「怎么分类」时，改它一次，两个数一起动 ——
而报告里只看得见一个动。** 修法是**把两个用途拆成两个函数**，而不是把两个数并排。

## F9 与派件里那句「允许表 = 我许它跑」的关系

**F9.1** 派件要求的是：**⑤ 的成因逐条归到【规则】还是【对象】还是【提取器】上**。
⇒ 本件的答案必须**按规则逐条给**，**不许**只给一个总数。

**F9.2** ★★ 若某一条规则挡下的处里，**绝大多数是它自己的误报**，**那一条必须单独点名** ——
因为**一条宽规则的误报会伪装成「我的射程很宽」**。

## F10 ★★★ 反引号标的是【代码】，不是【命令】

**F10.1** markdown 里一个反引号段标的是**代码**。它与**一条命令****不是同一个集合**。

逐字例子（都是**一个词**或**一段选项**，不是命令）：

```
python3
node
cmake
bash -e
```

**F10.2** ⇒ 把「有反引号」当成「是一条命令」，会把散文里**提到工具名的每一处**都收成候选。
★ 这与本项目里已发生过的**同一族**（一个**提取器的形状比它要提取的东西宽**）同族。

**F10.3** ⇒ 本件必须把「**是不是一条命令**」与「**有没有反引号**」当成**两个问题**，
并把前者的**判定依据逐条写出**。

## F11 ★★★ 一条【模板】与一条【字面量】是两种东西

**F11.1** 一条命令可以**写成一张填空表**：

```
git show <ref>:<path>
git show <你读的那棵树>:.gitignore | grep -cxF '/vtest/sayout.txt'
sed -n '<n>p' | wc -c
```

`<path>` 里的 `<` **不是一次重定向**，它是一个**占位符**。

**F11.2** ⇒ **【今天跑不动，因为它是一张填空表】**与**【今天跑不动，因为环境不在】**
是**两种不同的东西**，而**按字符判定**的规则**把它们归成同一条**。

**F11.3** ★★ 这与 **F7** 是**同族的两端**：F7 是**把字面量读成元字符**，
F11 是**把占位符读成元字符**。两端都**静默**，两端都**保持自洽**。

**F11.4** ⇒ 本件必须**把「含占位符」的那些处单独印出来**，并**逐处给出那个占位符是什么**。

## F12 ★★★ `git` 的子命令不是「第一个不以 `-` 开头的词」

**F12.1** 逐字反例：

```
git -C "$REPO_ROOT" diff --name-only "$range"
```

`-C` **带一个参数**。一个「跳过 `-` 开头的词、取下一个」的扫描器会取到
**`"$REPO_ROOT"`**，并把它读成**子命令**。

**F12.2** ⇒ **带参数的选项会让位置扫描读错对象**，而输出**保持自洽**
（它会报「子命令非只读：`$REPO_ROOT`」，读起来像一条真的发现）。

**F12.3** ⇒ 凡报「子命令非只读」的处，**必须逐处印出**，
并**逐处注明那个被读成子命令的词，是不是一个选项的参数**。

## F13 ★★★ 一个没有分辨力的代理量

**F13.1** 「可执行名能不能解析」对「**那一段反引号是不是一条命令**」**没有分辨力**：
一个单独的 `python3` **解析得到**。

**F13.2** ⇒ 一份 **188/188「代理上跑得动」** 的代理量，读起来像
**「允许表是唯一的拦路者」**，而真相可能是**那 188 处里绝大多数根本不是命令**。

**F13.3** ⇒ 报代理量时**必须与 F10 的判定并排**，
**不许**单独报一个 188/188 —— **一个分子等于分母的代理量，先怀疑那把尺子量错了对象。**
（同族：**一个恒为真的谓词不是一条读数**。）

## F14 ★★★ 单引号与双引号【不是同一种引号】

**F14.1** 在 shell 里：

| | `$` | `` ` `` | `\` |
|---|---|---|---|
| 单引号 `'…'` 里 | **字面量** | **字面量** | **字面量** |
| 双引号 `"…"` 里 | **仍会展开** | **仍会展开** | 部分转义 |

**F14.2** ⇒ 一个把两种引号**当成同一种**的「认引号」函数，
在**修好一个方向**（把单引号里的字面量放行）的同时，
**造出另一个方向**（把双引号里的 `$REPO_ROOT` 也放行了）。

**F14.3** ★★ **这与 F7 的缺陷是同一个形状** ——
**一条按字符判定的规则，不知道它读的那个字符处在什么语法位置。**
⇒ **修法本身带着被修的那个缺陷的形状，这是本件要求写进判据的一条。**

**F14.4** ⇒ 本件必须**单引号与双引号分开数**，
并**逐处印出双引号里含 `$` 或 `` ` `` 的那些处**（在 shell 里它们**仍会展开**）。

## F15 ★★★ 判「这条规则命中了吗」不许按【它的描述】

**F15.1** 逐字缺陷：谓词里写的是

```
/shell 元字符|不在允许表|git 子命令不在只读表|git 后面没有子命令|本探针不跑这一族/
```

而规则**印出来**的是

```
git 子命令非只读：mv
```

**`不在只读表` 与 `非只读` 不是同一个字符串。**

**F15.2** ⇒ **R4 挡下的每一处都在那个谓词上落空** ——
而**分母只会小一点，不会报错**，报告**逐项自洽**。

**F15.3** ★★ **这与本项目里已发生过的同一族**（一个**按行里出现的关键词**排除的规则，
排除掉的是**那个词**、不是**那一行的角色**）**同族**。

**F15.4** ⇒ 判定**一律按规则的键**（`R0`–`R5`），**不按它的描述字符串**。
⇒ 一般形式：**一条规则的名字与它被匹配时用的那个字符串，如果不是同一个字符串，
那么这条规则挡下的每一处都会静默地落空。**
**修法是把「命中」写成结构化的事实，不是把两个字符串抄得一样。**

## F16 ★★★ 白名单回答的是「在不在表上」，不是「它做什么」

**F16.1** 只读表是**11 项的白名单**。一条 `git` 子命令**不在表上**，
与它**实际上会不会改工作树**，是**两个不同的命题**。

**F16.2** 逐字证据：白名单**外**的真只读子命令至少有

```
git check-ignore -v      git archive      git reflog show
```

白名单**外**的、**真的会改工作树**的子命令至少有

```
git add -A   git commit   git mv   git rm   git checkout HEAD -- …
git stash push -- …   git merge --ff-only main   git worktree add --detach …
```

**F16.3** ⇒ 一条把两者归成同一档的规则，会让
**【真的会改工作树】与【真的只读】在报告里同形**，
而**总数只报一个数**。

**F16.4** ⇒ 本件必须**两个数并排**：
**「R4 那条规则挡下几处」** 与 **「按子命令语义判、实际上会改工作树的有几处」**，
并**逐处印出那些【真只读但不在白名单上】的**。

**F16.5** ★★ 一般形式（本件要求写进判据）：
**一个白名单能回答「它在不在表上」，回答不了「它做什么」。
凡用白名单当判据的地方，表外那一侧都是【一个没被定义的集合】。**

## F17 ★★ 写第二个脚本去复核第一个脚本的分母

**F17.1** 若本件用**第二个脚本**复核**第一个脚本**的分母，
**第二个脚本必须【逐字复用第一个脚本的那个谓词】**，**不许自己重写一遍**。

**F17.2** 逐字教训：一次复核里，第二个脚本把谓词重写成

```
/meta:|head:|sub:|R3|fam:/
```

而第一个脚本用的是描述字符串 ⇒ **两个脚本给出两个分母（244 与 188）**，
而**两者都自洽**。

**F17.3** ⇒ 一般形式：**复核的那把尺子如果与【被复核】的那把尺子不是同一把，
那么两个数的差不是【误差】，是【两把尺子的差】—— 它不能被读成一个读数。**
