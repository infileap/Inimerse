## 一、★★★ 头条一：`render_check.js:661` 落 **④ —— 三把都不收**

逐字：

```
render_check.js:661   己⁶′=false   庚⁶=false   壬⁶=false   ⇒ 键=000
```

**壬⁶ 看不见它的机制可指、且可关掉**（这就是本件的第三个对照）：

```
$ RULER_PERLINE=0 node website/scratch/ruler_ren6.js . | head -1
RULER=壬⁶(不看缩进)  DENOM=60
$ RULER_PERLINE=1 node website/scratch/ruler_ren6.js . | head -1
RULER=壬⁶(不看缩进)  DENOM=109
$ RULER_PERLINE=1 node website/scratch/ruler_ren6.js . | grep -c 'render_check.js:661'
1
```

⇒ **把语句切分器换成「逐行」，`:661` 立刻被收进来。**
**成因**：壬⁶ 的切分器用**绝对括号深度**判语句结束；而**函数体里的 `{` 从不归零** ⇒
**整个函数体被当成一条语句** ⇒ 函数体里任何一处 `&&` 都把它标成「有保护」。

★★★ **判据（署我名）：把造成盲区的那条规则拿掉，盲区不一定消失 —— 它换一个机制继续存在。「我删掉了那条规则」不是「我看见了那处」的读数。**
★ 三把尺子、三个互不相同的机制，`:661` 三把都看不见：己⁶（跳过声明 ＋ 列 0~2）／庚⁶（列 0~2）／壬⁶（**完全不看缩进**，被自己的语句切分器吃掉）。

★★★ **判据（署我名）：一个四档划分如果只按【第几把收】而不按【哪几把收】写，它就不能区分「三把都收」与「两把收、一把不收」。**
