## 三、有几处今天绿着而它的区间是错的 —— **0 处，而且这次有过输入**

把唯一那个活的定位器退化成历史缺陷的形状（`l.includes('CENSUS-BEGIN')`）：

```
红总数 = 4（基线 3）　检查项 644/648
新增的红【只有它】：㉛ 乙 ⑦：自扫描的枚举不许把自己数进去 —— ★ 而「排除了」必须是【被观测到发生过】的
  ← 哨兵行 = 3523 / 3538（跨度 15 行，必须 > 100）；射程内【确实被排除掉】的调用 = 0
     （必须 >= 1，本块自己那条就在里面）
     ★ 上一版写成 === 0，而它绿着 —— 因为它量错了区间：查找器把自己那一行当成了哨兵
```

**改前 / 改后逐字两行**（同一个 `info()`）：

```
改前    · ㉛ 乙 ⑦【分母：本文件里 check 调用总数】= 138　（哨兵行 3523 / 3652 圈出的射程内被排除 = 1 处）
改后    · ㉛ 乙 ⑦【分母：本文件里 check 调用总数】= 139　（哨兵行 3523 / 3538 圈出的射程内被排除 = 0 处）
```

★★ **注意那个分母动了：138 → 139。** 区间变短之后，被排除掉的那一条**回到了计数里** ——
「射程错了」在这个读数上的签名是**分母变大**，不只是「被排除 = 0」。
⇒ 判据：**一段区间的两端各自有一个可观测的后果：短了 ⇒ 被排除的那条跑进分母；
长了 ⇒ 不在这段里的东西跑进射程。只印「被排除 = 0」把这两个都藏起来了。**

## 四、我自己在这次普查里踩的第五次

变异脚本第一版的锚点缩进写错（`old` 里两个空格，文件里四个），`assert s.count(old)==1` 抛了 ——
**变异根本没落地**。而那一刻我手里的输出是「红总数 = 3（基线 3）」，与基线**一模一样**，
看上去完全像一次**漂亮的负对照**（「看，退化之后没有变化」）。
★ 把我拉回来的是**派件要求的那两行逐字对照**：改前与改后**逐字节相同** —— 一次真发生过的变异
不可能让那一行一个字都不动。
⇒ 判据：**「对照之后没有变化」与「对照没有发生」在输出里同形；
把它们分开的不是红数，是【那条被对照的东西自己动没动】。**
