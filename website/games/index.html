在线游戏

在浏览器里直接打开就玩。这个栏目现在还不能上，缺的不是代码，是两件外部条件。

结论先给：两条路各自缺一件东西，互不阻塞。 路一「托管到 B站 Toy」缺内测资格（平台侧邀请制）； 路二「在浏览器里跑引擎联机」缺浏览器运行时（引擎侧今天没有）。 所以这一栏的正确做法是先把位置和接入点做好，等条件到位再填内容。

B站 Toy 平台 等前置：内测资格

Toy 是 B站 2026 年推出的「互动内容发布平台」，把测试、小游戏、工具这类网页， 变成 B站站内点开就能玩的作品。

它到底是什么（官方原文）

以下引文来自官方介绍页 bilibili.com/toy/intro：

  • 「Toy是B站的互动内容发布平台。支持上传测试、小游戏、工具等创意，让大家在B站内直接体验。」
  • 「准备好互动作品后，在管理端填写信息并提交审核，通过后即可获得 Toy 链接。」
  • 「在 Toy 管理端上传文件，设置 Toy 名称、简介、封面与访问地址。」
  • 「平台会进行安全扫描和内容审核，确认通过后即可获得 Toy 链接。」
  • 「当前 Toy 发布面向邀请 UP 主逐步开放。具体权限、规则和审核要求，请以管理端提示和创作者协议为准。」

能不能嵌进本站？—— 不能，方向是反的

Toy 不是能嵌到别人站里的 iframe / SDK 型开放平台。 它是上传包体、由平台托管：作品页跑在 www.bilibili.com/toy/<slug>/index.html， 平台给你一条链接，你把它放进视频、动态、评论区。 所以「在线游戏」这一栏的接入方式是：本站放入口卡片，作品本体由 B站 托管。

有开放投稿接口吗？—— 有，官方 CLI

官方在 GitHub 发布了创作者 CLI（仓库 bilibili/toy，MIT）， 完成「发布 / 更新 / 预览 / 查询 / 视频绑定 / 排查」。 它不是只能人工在站内投稿——但发布权限本身仍是邀请制，接口开放不等于账号有权限。 安装后走服务端 OAuth 登录，带包体发布是「预览 → 确认 → 提交审核」两段式。

要适配的规则为什么
资源必须用相对路径页面跑在 /toy/<slug>/ 子路径下，绝对路径会白屏 / 404
路由用 hash 模式真实路径路由刷新会 404，除非每条路由都产出真实 HTML
只传构建产物，不传源码包里根目录或一层子目录下要有 index.html
slug 发布后不可改改地址只能删了重建，得不偿失
封面图不超过平台建议体积单个 HTML 文档过大时，打得开但每次都慢

本站已经按这几条约束建设（相对路径、无构建步骤、无外部 CDN 依赖）， 所以将来同一份产物可以原样打包上传，不需要为 Toy 再改一版。

现在缺的那一件事

内测资格。官方入口是「关注官号申请内测」/「私信官号申请内测」， 通过后由运营拉进 1v1 支持与社群。在拿到资格之前，这一栏无法上线任何作品， 不是技术问题，是权限问题。

作品位（等上线）

infiverse 联机 浏览器内今天做不到

「引擎本身能不能在浏览器里跑」和「仓库里有没有 wasm」是两件事。 仓库里确实有 wasm 后端，但那是编译器的 wasm 目标（把脚本编译成 wasm 模块）， 不等于引擎有一个浏览器运行时。

问题判定依据
引擎能在浏览器里跑吗 不能 wasm 后端生成的是独立模块，与浏览器宿主之间没有集成路径；且该子集不支持字符串
联机服务端能对外开吗 能开 CRP 中继是一个可运行的 HTTP + WebSocket 进程
那能不能玩联机 不能 中继负责信令与打包分发，没有任何浏览器可玩的对局前端

为什么「不能」

  • wasm 后端自述是独立模块，只接受零导入，而它自己导出 5 个 env 导入， 宿主侧根本没有对接路径 —— 也就是说，编译产物没有一个官方支持的浏览器宿主。
  • 那个 wasm 子集连字符串都不支持：把 say "hello" 编译成 wasm 会直接报错。 一个连文本输出都做不到的子集，不可能承载一个能玩的作品。
  • 后端按设计不访问文件系统、网络、DOM，所以联机所需的网络能力不在这一层。
  • 命令行里以 wasm 为目标直接运行会被明确拒绝，提示该后端尚未进入稳定通道。

那联机今天到哪一步了

中继（CRP，内容中继协议）是一个真实可跑的 HTTP + WebSocket 服务，负责注册、 查找、好友、NAT 候选、路由、会话租约、内容寻址与作品包分发。 引擎侧也有对应的服务端与平台层实现。它今天就能对外开——但它是个协调层， 不是游戏服务端。要让它在浏览器里有意义，还缺一个跑在浏览器里、能连上它的对局前端。
