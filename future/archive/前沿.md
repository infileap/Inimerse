## 第一部分：全息数据与可逆计算

### 一、全息数据

#### 1.1 核心原理

全息数据不是录屏，而是**完整记录游戏世界从初始状态开始的全部非确定性输入**。引擎本身是确定性函数：

```
世界状态(t+1) = F(世界状态(t), 输入(t), 随机种子(t), 网络消息(t))
```

只要保存了 `世界状态(0)` 和所有时刻的 `输入/随机种子/网络消息`，就能从头重放，逐帧还原整个宇宙。

#### 1.2 录制什么

| 数据 | 说明 | 数据量 |
|---|---|---|
| 初始快照 | 所有对象状态、全局变量 | 中等 |
| 玩家输入 | 键盘/鼠标/手柄事件 + 时间戳 | 极小（每秒几十字节） |
| 随机数种子 | 每个随机生成器的种子序列 | 极小 |
| 网络消息 | 所有传入包 | 小 |
| 事件日志 | `spi_emit` 等内部事件（可选） | 小 |

#### 1.3 确定性引擎要求

```c
// 确定性模式下的引擎保证
1. 浮点运算顺序固定（禁止非结合律优化）
2. 哈希表遍历顺序固定
3. 多线程可重现（记录线程切换点或单线程化）
4. 固定时间步长
5. 确定性随机数（PCG / xoshiro）
```

#### 1.4 语法与 API

```python
# 录制
holo_start("verse_timeline.holo")
# 游戏循环自动记录
holo_capture_frame()        # 每帧调用
holo_stop()

# 重放
holo_load("verse_timeline.holo")
holo_play()                 # 开始重放
holo_pause()
holo_seek(time_ms)          # 跳转到任意时间
holo_set_free_camera(true)  # 自由视角
holo_inspect(entity_id)     # 查看任意实体状态
holo_speed(2.0)             # 2 倍速
holo_reverse()              # 倒放
```

### 二、可逆计算

#### 2.1 核心原理

可逆计算要求**每个操作都有逆操作**。这样无需保存快照就能撤销到任意历史状态。

```
操作 f: 状态 A → 状态 B
逆操作 f⁻¹: 状态 B → 状态 A
```

#### 2.2 语法

```python
# 可逆块
reversible {
    player.hp -= 10
    player.position.move(5, 5)
    spawn_monster()
}
# 之后可以：
rollback()          # 撤销整个块
commit()            # 确认，丢弃逆操作日志
```

#### 2.3 实现方式

```c
// 操作日志
typedef struct {
    OpType type;
    union {
        struct { Object* obj; int field; Value old_val; } field_set;
        struct { Object* obj; double dx; double dy; } position_move;
        struct { Object* obj; } object_spawn;
    };
} ReversibleOp;

// 执行操作时记录逆操作
void reversible_field_set(Object* obj, int field, Value new_val) {
    ReversibleOp op = {
        .type = OP_FIELD_SET,
        .field_set = {obj, field, obj->fields[field]}
    };
    push_op_log(&op);
    obj->fields[field] = new_val;
}

// 回滚：从后往前执行逆操作
void rollback() {
    while (!op_log_empty()) {
        ReversibleOp op = pop_op_log();
        switch (op.type) {
            case OP_FIELD_SET:
                op.field_set.obj->fields[op.field_set.field] = op.field_set.old_val;
                break;
            case OP_POSITION_MOVE:
                op.position_move.obj->x -= op.position_move.dx;
                op.position_move.obj->y -= op.position_move.dy;
                break;
            case OP_OBJECT_SPAWN:
                destroy_object(op.object_spawn.obj);
                break;
        }
    }
}
```

#### 2.4 与传统快照的对比

| 特性 | 快照 | 可逆计算 |
|---|---|---|
| 内存占用 | 大（完整状态） | 小（只记录变化） |
| 回滚速度 | 快（直接恢复） | 慢（逐个撤销） |
| 精确度 | 粗粒度（快照点） | 细粒度（任意操作） |
| 适合场景 | 定期备份 | 短时间内精确回滚 |

#### 2.5 组合：快照 + 可逆

```
快照（每 10 秒）
  ↓
可逆操作日志（快照之间）
  ↓
回滚时：恢复到最近快照 + 撤销之后的日志
```

#### 2.6 在 Infiverse 中的应用

| 场景 | 说明 |
|---|---|
| 热修改失败回滚 | 撤销失败的修改，恢复稳定状态 |
| 时间旅行调试 | 在调试器中反向执行，观察变量演化 |
| 分支探索 | 尝试不同策略，安全回滚到分支点 |
| 玩家撤销操作 | 误操作后回退 |

## 第二部分：概率编程与前沿理论

### 一、概率编程

#### 1.1 核心思想

随机变量作为**一等公民**，支持概率分布、条件采样、贝叶斯推理。

```python
# 概率属性
attack ~ Normal(mean=15, std=3)
hp ~ Uniform(80, 120)

# 条件概率
if rand() < aggression * night_factor {
    attack_player()
}
```

#### 1.2 支持的概率分布

| 分布 | 语法 | 用途 |
|---|---|---|
| 正态分布 | `Normal(μ, σ)` | 伤害浮动、AI 决策 |
| 均匀分布 | `Uniform(a, b)` | 随机位置、战利品 |
| 伯努利 | `Bernoulli(p)` | 触发率、暴击 |
| 指数 | `Exponential(λ)` | 等待时间、事件间隔 |
| 泊松 | `Poisson(λ)` | 刷怪数量 |

#### 1.3 在 Infiverse 中的应用

| 场景 | 说明 |
|---|---|
| AI 居民行为 | 概率图模型，观察学习动态更新 |
| 自适应难度 | 根据玩家表现调整参数 |
| 概率反作弊 | 计算玩家行为属于作弊的后验概率 |
| 宇宙法则 | 天气、生态、经济系统的随机性 |

#### 1.4 实现

```python
# 声明概率属性
eidos Monster {
    attack ~ Normal(15, 3)

    on_update {
        # 每次攻击时从分布采样
        damage = sample(attack)
        player.take_damage(damage)
    }
}

# 条件依赖
eidos Weather {
    state be {"sunny", "rainy", "stormy"}

    # 转移概率矩阵
    transition ~ {
        "sunny" -> {"sunny": 0.8, "rainy": 0.15, "stormy": 0.05},
        "rainy" -> {"sunny": 0.3, "rainy": 0.5, "stormy": 0.2},
        "stormy" -> {"sunny": 0.2, "rainy": 0.4, "stormy": 0.4}
    }

    on_update {
        state = sample(transition[state])
    }
}
```

### 二、范畴论组合子

#### 2.1 核心思想

用**计算表达式**（类似 F# computation expressions）将复杂工作流组合为可读的形式。

```python
verse_flow {
    let! player = spawn(Player)
    let! monster = spawn(Monster)
    do! fight(player, monster)
    return player.hp
}
```

#### 2.2 与集合类型的结合

```python
# 计算表达式的类型 = 集合映射
# spawn(Player) : 空 → Player
# fight(Player, Monster) : (Player, Monster) → BattleResult
# 整体：空 → BattleResult
```

#### 2.3 在 Infiverse 中的应用

| 场景 | 说明 |
|---|---|
| 宇宙创建流程 | 初始化世界 → 生成实体 → 设置法则 |
| 任务系统 | 接受任务 → 完成目标 → 获得奖励 |
| 交易流程 | 检查余额 → 转移资产 → 更新记录 |
| 异步操作链 | 网络请求 → 处理响应 → 更新状态 |

#### 2.4 实现示例

```python
# 任务系统的计算表达式
quest_flow {
    let! quest = accept_quest(player, "击败哥布林")
    let! result = fight(player, goblin_group)
    if result.won {
        do! grant_reward(player, quest.reward)
    } else {
        do! fail_quest(player, quest)
    }
    return result
}

# 等价于嵌套回调，但更可读
```

### 三、量子启发式叠加

#### 3.1 核心思想

变量可以同时处于多个状态（叠加），直到被“测量”才坍缩。用于模拟平行宇宙分支。

```python
state = superposition([WorldA, WorldB])
choice = measure(state)    # 随机坍缩到其中之一
```

#### 3.2 在 Infiverse 中的应用

| 场景 | 说明 |
|---|---|
| 平行宇宙探索 | 同时模拟多个分支，选择最优 |
| 搜索优化 | 量子式搜索：在巨大空间快速找到解 |
| 剧情分支 | 玩家可以探索所有可能的选择 |
| AI 决策 | 同时评估多个策略，测量后执行 |

#### 3.3 与平行宇宙协议的结合

```python
# 叠加多个宇宙
verse_state = superposition([verse_A, verse_B, verse_C])

# 在叠加态上执行操作（同时作用于所有宇宙）
verse_state.apply(lambda v: v.spawn_monster())

# 测量（选择保留的宇宙）
chosen = measure(verse_state)
```

#### 3.4 实现（模拟）

```c
// 叠加态 = 可能值列表
typedef struct {
    Value* possibilities;
    int count;
    double* weights;       // 每个可能性的权重（振幅平方）
} Superposition;

// 测量：按权重随机选择
Value superposition_measure(Superposition* s) {
    double total = sum(s->weights);
    double r = random_double() * total;
    for (int i = 0; i < s->count; i++) {
        r -= s->weights[i];
        if (r <= 0) return s->possibilities[i];
    }
    return s->possibilities[s->count - 1];
}
```

### 五、线型类型

#### 5.1 核心思想

资源必须**恰好使用一次**。防止泄漏和重复使用。

```python
linear file = open_file("data.txt")
content = file.read()      # 使用一次
# file 在使用后自动销毁，之后不能再访问
```

#### 5.2 在 Infiverse 中的应用

| 场景 | 说明 |
|---|---|
| 文件句柄 | 自动关闭，无泄漏 |
| 网络连接 | 自动断开 |
| 原生内存 | 自动释放 |
| 宇宙权限令牌 | 使用后失效 |

#### 5.3 实现

```c
// 编译期检查
void check_linear_usage(VarInfo* var) {
    if (var->is_linear && var->use_count > 1) {
        error("线型变量 %s 被使用多次", var->name);
    }
    if (var->is_linear && var->use_count == 0) {
        warning("线型变量 %s 未被使用", var->name);
    }
}
```

### 六、证明携带代码

#### 6.1 核心思想

代码附带**形式化证明**，加载时快速验证。若通过则直接运行，否则拒绝或降级到沙盒。

```python
proof {
    forall player, player.hp >= 0
}
```

#### 6.2 在 Infiverse 中的应用

| 场景 | 说明 |
|---|---|
| 宇宙包加载 | 验证安全性后免沙盒运行 |
| 第三方模组 | 降低对 `isolate_run` 的依赖 |
| 经济系统 | 证明不会产生通货膨胀 |
| 内存安全 | 证明无悬垂指针 |

#### 6.3 证明示例

```python
# 宇宙包
proof {
    # 不变量：所有玩家血量非负
    forall p in Player, p.hp in N

    # 不变量：货币总量不增
    total_gold_before >= total_gold_after
}
```

## 三、总结

| 特性 | 本质 | 对 Infiverse 的意义 |
|---|---|---|
| 全息数据 | 确定性重放 | 可审计、可回溯、可再创造的历史 |
| 可逆计算 | 操作有逆 | 完美回滚、时间旅行调试 |
| 概率编程 | 随机变量一等公民 | 更真实的 AI 与自适应世界 |
| 范畴论组合子 | 可组合的工作流 | 复杂宇宙逻辑的形式化表达 |
| 量子启发叠加 | 多状态并行 | 平行宇宙分支探索 |
| 程序合成 | 示例生成代码 | 降低创作门槛 |
| 线型类型 | 资源恰好一次 | 系统级安全 |
| 证明携带代码 | 代码带证明 | 免沙盒运行，提升性能 |

这些前沿理论并非空中楼阁——它们各自在实验语言和系统中已有实践。Inimerse 的独特之处在于将它们**统一在一个为多宇宙而生的平台上**，让创造者既能享受理论带来的安全与智能，又不被理论束缚。
