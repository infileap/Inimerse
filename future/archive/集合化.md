# 类型集合化完整文档（修订版）

## Inimerse 基于集合论的类型系统

---

## 一、核心哲学

在 Inimerse 中，**一切类型都是集合**。`in` 同时表达“属于”和“子集”，编译器根据左操作数自动判断。

```
42 in N                 # 属于（左边是值）
Z+ in N                 # 子集（左边是集合）
```

---

## 二、好处与风险

### 2.1 好处

| 好处 | 说明 |
|---|---|
| **统一性** | 类型、精化、约束、状态机共用一套语言 |
| **可组合性** | `+` `*` `-` 三个运算自然组合类型 |
| **数学清晰** | 基于集合论的坚实基础，易于推理 |
| **编译期安全** | 子集关系静态证明，消除运行时检查 |
| **优化潜力** | 类型信息驱动特化、向量化、代码消除 |
| **宇宙法则验证** | 宇宙变换 = 集合映射，可由编译器验证 |
| **渐进式类型** | 从完全动态逐步细化到精确集合 |
| **AI 友好** | 集合定义简洁明确，LLM 易于理解和生成 |

### 2.2 风险

| 风险 | 说明 | 缓解方案 |
|---|---|---|
| **不可判定性** | 任意谓词可能导致子集判断不可判定 | 限定谓词为可判定片段（线性算术、位向量、有限枚举） |
| **运行时检查开销** | 无法静态证明时需插入运行时检查 | 循环不变量外提；JIT 特化消除 |
| **动态性冲突** | 热修改/宇宙变换使类型假设失效 | 版本号失效；反优化点；通用回退路径 |
| **编译时间增长** | 复杂集合表达式导致编译变慢 | 缓存运算结果；限制嵌套深度 |
| **学习曲线** | 集合思维对部分开发者陌生 | 渐进式类型，不强制的可选标注 |
| **过度约束** | 过窄的集合限制灵活性 | `be` 标注可随时移除或放宽 |

## 三、内置集合的删改意见

### 3.1 现有内置集合

| 集合 | 含义 | 保留/删改 | 建议 |
|---|---|---|---|
| **N** | 非负整数（含 0） | ✅ 保留 | 核心集合 |
| **Z** | 全体整数 | ✅ 保留 | 核心集合 |
| **Z+** | 正整数（不含 0） | ✅ 保留 | 核心集合 |
| **Z-** | 负整数（不含 0） | ⚠️ 可保留 | 使用频率低，但对称性需要 |
| **R** | 有限实数 | ✅ 保留 | 核心集合 |
| **FloatN** | 恰好 N 位小数 | ⚠️ 建议删除 | 使用频率极低，且可用谓词替代 |
| **floatN** | 不超过 N 位小数 | ⚠️ 建议删除 | 可用谓词替代 |

### 3.2 删改理由

**FloatN / floatN 的问题**：

1. **语义不自然**：`Float1` 和 `float1` 的区别（恰好 vs 不超过）容易混淆。
2. **替代方案简单**：
   ```python
   # float2 的替代
   float2 = {x in R | round(x * 100) == x * 100}
   ```
3. **N 的取值不明确**：Float1 到 Float9，为什么只到 9？二进制浮点无法精确表示十进制小数，语义存在歧义。
4. **使用频率低**：实际代码中极少需要“恰好一位小数”的类型。

**建议**：

- 删除 `Float1`-`Float9` 和 `float1`-`float9`。
- 如需此类约束，用谓词集合定义：`price = {x in R | x * 100 in Z}`。
- 保留 N、Z、Z+、Z-、R 作为基础集合。

### 3.3 建议补充的内置集合

| 集合 | 含义 | 理由 |
|---|---|---|
| **Q** | 有理数（可选） | 用于精确数学运算 |
| **Bool** | `{true, false}` | 统一类型体系 |
| **Str** | 所有字符串 | 统一类型体系 |
| **Any** | 所有值 | 联合类型的基础 |
| **Empty** | 空集 | 表示不可能的类型 |

## 四、与精化类型的结合

### 4.1 精化类型 = 集合交集

传统精化类型写作 `x: int where x > 0`，在集合系统中自然表达为：

```python
positive = Z * {x in Z | x > 0}
# 或更简洁
positive = Z * (0, )    # 使用无界区间
```

### 4.2 组合精化

```python
# 多层精化
hp_type = N * [0~100] * {x in Z | x % 2 == 0}   # 非负、≤100、偶数

# 命名精化
type EvenHP = N * [0~100] * {x in Z | x % 2 == 0}
```

### 4.3 与 Eidos 不变量统一

```python
eidos Player {
    hp be N * [0~max_hp]
    # 等价于
    # invariant { hp >= 0 and hp <= max_hp }
}
```

### 4.4 前置/后置条件

```python
eidos Player {
    take_damage(n be Z+) {
        # 前置条件：n in Z+
        hp -= n
        # 后置条件：hp in N * [0~max_hp]
        if hp < 0 { hp = 0 }
    }
}
```

编译器验证方法调用前后集合成员关系是否保持。

### 4.5 精化类型的运行时成本控制

```python
# 编译器自动决定：静态证明 or 运行时检查

# 情况 1：可静态证明
x = 5
y be Z+ = x          # 编译器知道 5 in Z+，无运行时检查

# 情况 2：需要运行时检查
x = user_input()
y be Z+ = x          # 自动插入：if !(x in Z+) raise TypeError

# 情况 3：循环内检查外提
for i in range(100) {
    # 编译器将检查移出循环
    val be Z+ = arr[i]
}
```

## 五、语法总览

### 5.1 类型声明：`be`

```python
x be N                       # x 是非负整数
hp be N * [0~100]            # hp 在 0 到 100 之间
level be Z+                  # level 是正整数
price be {x in R | x * 100 in Z}   # 最多两位小数
name be {s in Str | len(s) > 0}    # 非空字符串
state be {"alive", "dead"}   # 枚举状态
```

### 5.2 集合定义

```python
# 枚举
a = {1, 2, 3}

# 区间
b = [1~10]        # 整数区间
c = [1, 10)       # 左闭右开
d = (1, 10]       # 左开右闭
e = (1, 10)       # 开区间
f = [ , 5]        # x <= 5
g = [5, )         # x >= 5
h = R[0.0~1.0]    # 实数区间

# 谓词
positive = {x in Z | x > 0}
```

### 5.3 集合运算

```python
# 并集：+
int_or_str = Z + Str
number = Z + R

# 交集：*
safe_hp = N * [0~100]
positive = Z * (0, )

# 差集：-
nonzero = Z - {0}
```

## 六、完整示例

```python
# 集合定义
max_hp = 100
safe_hp = N * [0~max_hp]        # 非负且不超过 100
positive = Z+                    # 正整数
money = {x in R | x * 100 in Z}  # 最多两位小数
element = {"fire", "ice", "lightning"}
battery = [0~100]

# Eidos
eidos Player {
    hp be safe_hp
    level be positive
    gold be money
    element be element + nil     # 可为空

    take_damage(n be positive) {
        hp -= n
        if hp < 0 { hp = 0 }
    }

    heal(n be N) -> hp be safe_hp {
        hp += n
        return hp
    }
}

# 宇宙变换
eidos MagicalSword {
    element be element
    damage be positive
}

eidos CyberBlade {
    energy be battery
    damage be positive
}

verse_mapping MagicalSword -> CyberBlade {
    element -> battery
    positive -> positive
}

# 使用
p = Player(hp = 100, level = 1, gold = 99.99, element = "fire")
p.take_damage(30)          # 编译通过：30 in positive
p.take_damage(-5)          # 编译错误：-5 not in positive
p.hp = -10                 # 编译错误：-10 not in safe_hp
p.gold = 3.14159           # 编译错误：3.14159 not in money
```

## 七、设计总结

| 原则 | 实现 |
|---|---|
| 一个关键字 | `in` 同时表达属于和子集 |
| 三个运算符 | `+`（并集）、`*`（交集）、`-`（差集） |
| 声明即约束 | `be` 语句 = 集合成员关系 |
| 精简内置集合 | N、Z、Z+、Z-、R（删除 FloatN/floatN） |
| 区间语法 | `[a~b]`、`[a,b)`、`(a,b]`、`(a,b)`、`[ ,b]`、`[a, )` |
| 继承即子集 | `Eidos: Parent` = `Eidos in Parent` |
| 宇宙变换即映射 | `verse_mapping` = 集合映射 |
| 精化类型即交集 | `N * {x | x > 0}` |
| 不变量即成员 | `invariant` = 恒真的成员关系 |
| 渐进式 | 可选标注，可随时添加/移除 |

**类型集合化的本质：用最少的语法（`be` + `in` + `+ * -`），表达最丰富的类型信息，为编译优化和宇宙法则验证提供数学基础。内置集合保持精简，复杂类型通过组合运算构建。**
