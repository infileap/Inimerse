# Inimerse 函数式原生支持与统一错误处理

## 一、统一哲学：一切皆数据

函数式编程与错误处理共享同一个核心原则：**把一切（值、错误、函数、集合）都当作数据来流转变换。**

```
传统：  try { 操作 } catch(错误) { 处理 }    ← 控制流思维
Inimerse：操作 |> transform |> case { ... }  ← 数据流思维
```

这使函数式表达与错误处理天然融合，形成一套连贯、简洁、可组合的代码风格。

## 二、函数式原生支持（精简版）

### 2.1 管道：函数式灵魂

```python
# 数据从左到右流动，消除嵌套
result = data
    |> parse
    |> validate
    |> transform
    |> save
```

### 2.2 Lambda 与高阶函数

```python
# lambda：x -> expr
doubled = arr.map(x -> x * 2)
alive = arr.filter(x -> x.hp > 0)
total = arr.reduce(0, (acc, x) -> acc + x)
```

### 2.3 集合推导：声明式的极致

```python
# 比 map/filter 更直观
alive_attacks = {m.attack | m in Monsters, m.hp > 0}
```

### 2.4 函数组合（进阶）

```python
# 将多步变换组合为一个函数
process = parse >> validate >> transform
result = process(data)
```

### 2.5 不可变数据：正确性的基础

```python
eidos Config {
    frozen max_hp = 999      # 不可变
    frozen name = "game"
}
```

### 2.6 安全访问与空值合并

```python
city = user?.address?.city
port = config?.server?.port ?? 8080
```

## 三、统一错误处理：集合化错误 + case try

### 3.1 错误类型是集合

```python
type FileError = {
    "not_found",
    "permission_denied",
    "disk_full"
}

type AppError = FileError + ParseError    # 集合并集组合
```

每个成员自动成为符号常量，可直接返回：

```python
func read_file(path) -> Result(Str, FileError) {
    if !file_exists(path) { return not_found }    # 自动包装 Err
    return content                                  # 自动包装 Ok
}
```

### 3.2 case try：统一处理

```python
case try read_file("config.json") {
    content => use(content)              # 成功
    not_found => create_default()        # 错误
    permission_denied => say("无权限")
    e => say("其他错误：" + e)
}
```

`try` 只捕获错误，不处理；`case` 统一处理成功与失败。

### 3.3 ? 运算符：错误传播

```python
func load_config(path) -> Result(Config, AppError) {
    content = try read_file(path) ?        # Err 直接返回
    config = try parse_config(content) ?
    return config
}
```

### 3.4 与函数式管道融合

```python
result = raw_data
    |> parse                  # 每个步骤返回 Result
    |> validate
    |> transform
    |> save
    |> case {
        ok => say("成功")
        err => say("失败：" + err)
    }
```

**关键**：管道中每步返回 Result，任何一步失败自动短路，错误作为数据继续流向下游。

## 四、两者融合：声明式错误安全管道

### 4.1 完整示例

```python
# 定义错误集合
type LoadError = FileError + ParseError

# 纯函数管道：每个步骤返回 Result
func load_player(id) -> Result(Player, LoadError) {
    read_file("players/" + id + ".json")       # Result(Str, FileError)
        |> validate_not_empty                   # Result(Str, LoadError)
        |> parse_json                           # Result(Object, ParseError)
        |> build_player                         # Result(Player, ...)
}

# 使用：声明式处理所有情况
case try load_player("alice") {
    player => say("欢迎回来，" + player.name)
    not_found => say("玩家不存在")
    empty_file => say("数据为空")
    invalid_format => say("数据损坏")
    e => say("未知错误：" + e)
}
```

### 4.2 错误恢复的管道

```python
fetch_data(url)
    |> catch(timeout, e -> fetch_data(backup_url))
    |> catch(offline, e -> use_cache())
    |> case {
        data => process(data)
        error => fallback()
    }
```

### 4.3 函数式错误处理器

```python
# 错误处理器是函数，可复用
handle_file_errors = catch {
    not_found => create_default()
    permission_denied => say("无权限")
    disk_full => say("磁盘已满")
}

result = read_file(path) |> handle_file_errors
```

## 五、集合推导与错误安全

```python
# 在集合推导中也可以安全处理错误
valid_results = {
    value | x in data,
    (value = try parse(x)) is Ok
}

# 或者收集错误
errors = {
    e | x in data,
    (e = try parse(x)) is Err
}
```

## 六、核心语法速查卡

| 分类 | 语法 | 说明 |
|---|---|---|
| **管道** | `\|>` | 数据从左到右 |
| **Lambda** | `x -> expr` | 匿名函数 |
| **变换** | `.map(f)` `.filter(p)` `.reduce(i,f)` | 三大高阶 |
| **推导** | `{f(x) \| x in S, cond}` | 声明式集合 |
| **组合** | `f >> g` | 函数组合 |
| **不可变** | `frozen x = 5` | 不可变数据 |
| **安全访问** | `a?.b?.c` | 可选链 |
| **空值合并** | `a ?? default` | 默认值 |
| **Result 类型** | `Result(T, E)` | 成功或错误 |
| **快捷返回** | `return not_found` | 自动 Err |
| **统一处理** | `case try op() { ... }` | 错误处理 |
| **传播** | `op() ?` | 错误上抛 |
| **错误恢复** | `op() \|> catch(e -> ...)` | 管道恢复 |
| **错误处理器** | `catch { A => ..., B => ... }` | 复用处理 |

## 七、设计原则

| 原则 | 说明 |
|---|---|
| **数据流优先** | 管道和 Result 让错误自然流动 |
| **错误即集合** | 错误类型是集合，成员是符号常量 |
| **case 统一处理** | 成功和失败一视同仁 |
| **编译器穷尽检查** | 所有错误分支必须覆盖 |
| **零成本错误** | 成功路径 ~2ns，错误路径比异常快千倍 |
| **可组合** | 管道、组合、推导、错误处理自由组合 |
| **AI 友好** | 类型签名清晰，约束可验证 |

---

## 八、核心优势

```
简洁性：return not_found，而非 Err("not_found")
一致性：错误和值都是数据，都通过管道和 case 处理
安全性：编译器穷尽检查，消除遗漏
性能：成功路径~2ns，错误路径~2ns（比异常快千倍）
可组合：管道 |> case try |> 错误处理器
```

**Inimerse 将函数式编程与错误处理融合为一件事：数据的流转变换。** 错误不是旁路，而是数据流中自然的一部分。这使代码更简洁、更安全、更可组合。

**这是集合论哲学的必然结果：一切皆集合，错误是集合成员，处理是模式匹配，流动是管道变换。**
