# Infiverse 完全构想

## 序言：宇宙常数宣言

Infiverse（Infinity + Universe）不是一款游戏。

它是所有游戏可以同时存在的底层协议。是一个去中心化、可编程、永恒演化的多元宇宙基础设施。它不提供单一世界，不预设单一玩法，不定义单一目标。它只做一件事：**颁布一套不可动摇的宇宙物理常数**，然后退后，让所有玩家、创造者、管理员和AI在这套常数之上，创造无限多个完全自治、法则各异的平行宇宙。

正如我们的现实宇宙诞生时，物理定律被颁布：光速、引力常数、量子规则。此后一百三十八亿年，星系旋转、恒星燃烧、生命涌现、文明兴衰——一切都在这些不变的常数下自然发生。物理定律从不干涉生命如何生活，它只决定什么可能、什么不可能。

**Infiverse 就是虚拟宇宙的物理定律。**
**Inimerse 就是这些定律的第一个可运行实现。**

# 第一部分：核心哲学

### 1.1 三项不可动摇的原则

**原则一：我们创造常数，你们创造宇宙**

Infiverse 的开发者只维护底层协议——坐标系统、空间结构、传送寻址、模组接口、资产同步规则。绝不干涉任何宇宙内部的内容与规则。不提供“主线任务”，不制造“官方货币”，不设定“世界观”。每一条意见、每一个偏好、每一个规则，都属于宇宙的创造者，而不是协议本身。

**原则二：协议不变，实现可换**

核心协议设计为永恒的。接口可以扩展，但绝不破坏旧方法。今天写的模组，十年后依然能运行。运行时代码可以被重写一百遍，但协议语义保持稳定。这意味着一件事：**创作者可以放心地构建，而不用担心某天醒来，发现自己的宇宙因为“版本更新”而崩塌。**

**原则三：信息透明，价值自决**

Infiverse 不定义什么是“值钱的”，不发行中央货币，不评级玩家。它只提供不可篡改的溯源和声誉基础设施。所有的价值判断，留给市场、留给社区、留给每一个 Traveller 自己的选择。

### 1.2 三层宇宙结构

Infiverse 运行时，会自动涌现出三层结构：

**第一层：本底宇宙（The Substrate）**

这是 Infiverse 的核心协议本身。由开发方维护。它定义空间拓扑、传送协议、模组接口、资产规则。它极其稳定，更新以年为单位，每次更新都是向后兼容的扩展。

**第二层：创世神域（The Genesis Realms）**

这是由服务器管理员、模组作者和宇宙创造者构建的世界。每一个“神域”都是一个完整的、自治的宇宙，拥有自己的法则、物理、经济、文化。一个创造者可以用 Verse Forge 定义一个修仙世界，另一个可以定义一个赛博朋克世界，第三个可以定义一个纯粹的抽象数学世界。它们之间默认完全隔离，互不干扰。

**第三层：涌现与连接（The Emergent Web）**

当第二层足够繁荣时，跨宇宙的活动会自然涌现。寻址师穿梭于世界之间，记录传送门密码。商人利用平行宇宙协议进行跨宇宙套利。佣兵团在不同宇宙中建立分部，互相支援。这些活动不被预设，但被协议允许。它们是多元宇宙的生命力所在。

# 第二部分：空间架构

### 2.1 五层空间模型

Infiverse 采用严格的空间层级结构：

```
服务器 (Server)
 └─ 层级组 (Verse / Layer Group)
     └─ 层级 (Layer)
         └─ 区块 (Block / Chunk)
             └─ 方格 (Cell / Voxel)
```

**方格（Cell）**：最小交互单位。用于移动、放置方块、修改地表。一个方格在世界中有一个唯一的坐标键。

**区块（Block）**：由多个方格组成的区域，是空间逻辑的基本单位。区块具有类型：
- **闭区块**：周围有墙或障碍物。某些情况下，区块内的角色看不到区块外的事物（通过迷雾、黑暗等效果实现）。
- **开区块**：与外界无阻隔，但可能与相邻区块有不同特性（如生态群系差异）。
- **连区块**：多个区块连在一起成为大区块。

区块的相邻关系可以由插件自定义。这是非欧几里得几何的入口点。

**层级（Layer）**：一个完整的地图平面。坐标以 (X, Y) 表示。
- X 和 Y 的取值默认为 -255 到 +255（包括 0），以及一个特殊值 i。
- 这些加起来正好 512 种取值。
- 主层级为 (0,0)，四极（对应地球南北极）为 (±255, ±255)。
- 虚层级的 X 和 Y 值中至少有一个为 i。
- 每个层级可以有不同的机制，地图完全不一样。
- 层级可以由种子码生成，也可以是随机生成（来到下一个区块时才生成新的区块）。
- 虚层级怪物生成较多，且区块内怪物上限较高。
- 混沌层级 (i,i)：当一个区块没有玩家角色时，下一次有玩家角色进入则重新生成。这意味着每次进入都会看到新的区块，适合冒险玩家。

**层级组（Verse）**：多个层级的逻辑集群，拥有统一的世界法则、经济系统和传送门映射规则。不同层级组之间默认物品、能力不互通，保证每个 Verse 的独立性。层级组中可设置物品/属性互通、传送对应（类似 MC 主世界和下界通过地狱门的坐标对应）。

**服务器**：物理主机，可承载多个层级组。

### 2.2 虚层级与八格映射

虚层级（坐标中至少含有一个 i）是一个充满神秘色彩的空间。它比主世界更危险、更不稳定，但也更强大。

**八格映射规则**：虚层级一格对应相同层级组中其他层级八格。

这意味着什么？想象一个主世界中的巨大城墙，绵延八百里。在对应的虚层级中，你只需要走一百里，就能绕过这道城墙。虚层级是一个“压缩空间”，在这里移动一小步，回到主世界可能就是一大步。

这是天生的策略空间：
- **战争**：利用虚层级绕过防线，直接出现在敌人后方。
- **贸易**：在虚层级建立快速运输线路。
- **探索**：虚层级可能藏着主世界无法到达的秘境。

### 2.3 非欧几里得几何

每个 Verse 都可以定义自己的空间拓扑。这是通过修改区块邻接表实现的。

**平坦（欧几里得）**：默认的网格相邻关系。上下左右四个方向，符合直觉。

**球面**：世界有限无界。一直朝同一方向走，最终会回到原点。整个层级只有有限个区块，但没有边界。三角形内角和大于 180 度。

**双曲**：空间呈指数级扩张。一个点的周围可以容纳远超欧几里得空间的区块。两个玩家从同一点出发，分别向不同方向走，他们会以惊人的速度永远分离。没有 GPS 能在这里工作。视野扭曲，小地图自我折叠。这是最令人不安的空间拓扑。

**自定义邻接表**：手工定义任意区块的连接关系。一个房间的六面墙各自通向完全不相邻的区块。你可以建造一个只有三个房间但永远走不到尽头的迷宫。这是“不可能空间”在离散网格上的完美实现。

非欧几何不只是噱头，它会根本性地改变玩家的行为模式：
- 寻址师噩梦：在双曲空间中，传送门坐标的八格映射规则完全崩溃。需要全新的密码本。
- 基地防御重构：球面世界没有“后方”，任何方向都可能遭到攻击。
- 迷宫与宝藏：手工拓扑的空间是天然的、无法被常规逻辑破解的迷宫。

# 第三部分：传送门系统

### 3.1 蜡烛二进制寻址

传送门是 Infiverse 中最核心的交互对象之一。它不只是一扇门，而是一套完整的密码锁系统。

**基本机制**：传送门通过门框上的蜡烛（或替代输入设备）的亮灭状态进行编码。每一根蜡烛代表一个二进制位。一组蜡烛的排列构成目标层级的访问密码。

**坐标编码**：512×512 的坐标空间 = 262,144 种可能性 = 恰好 18 位二进制（2^18 = 262,144）。低 9 位编码 X 坐标（+255 偏移），高 9 位编码 Y 坐标。

**密码扩展**：18 位只是基础。通过扩展蜡烛数量（32 位、64 位）和哈希映射协议，可以实现几乎无限多的密码空间。多个密码可以指向同一个层级，而管理者只分发其中一个给访客。

**仪式感**：这不是点击一个 UI 按钮。玩家需要亲手点亮和熄灭蜡烛，每一根蜡烛都对应一个符文在门框上亮起或熄灭，发出不同的嗡鸣声。当输完一个不存在的地址时，所有蜡烛火焰瞬间变成诡异的紫色，然后全部熄灭，门中传来一声悠远空洞的叹息。这是“可触知的魔法”。

### 3.2 传送门的建造学

传送门本身是可以被建造和改造的：

**门框材质影响稳定度**：普通石制门框可能只能承载前 256 个基础层级。要通往高危险度的虚层级或加密的私人层级，门框需要用稀有材料建造，否则会在传送瞬间炸毁。

**蜡烛的品级**：普通蜡烛点一次可能就消耗了。龙脂蜡烛或永不熄灭的魂火灯可以永久固化地址。

**输入设备的美学拓展**：不一定是蜡烛。森林精灵的传送门可能是控制七朵花苞的开合。机械废土的门则是一排拨动开关。核心是二进制，但皮肤千变万化。

### 3.3 寻址学与骇客生态

传送门系统催生出多元宇宙中最丰富的职业生态：

**寻址师**：记录和交易有效蜡烛阵型。他们拥有一本记满了各种宇宙密码的笔记本，靠出售这些信息为生。一个顶级寻址师的身价，可能超过一个完整宇宙的价值。

**骇客**：利用嗅探器（分析传送门能量流动）、暴力破门器（自动尝试所有密码组合）、漏洞扫描器（利用门框材质缺陷）等工具入侵他人的传送门网络。这不是简单的作弊，而是一种需要智力、耐心和运气的竞技活动。

**社会工程**：最高级的入侵方式。伪装成新手向老玩家骗取一次性密码。或者故意售卖一个看似很有价值实则由你控制的“安全房”层级密码，等着对方在里面存放所有家当。

**防御者**：白帽寻址师受雇于公会进行渗透测试。门锁匠联盟研究更好的门框材料和蜡烛。安全顾问为大型宇宙设计多层防御。

### 3.4 VDP：宇宙分发协议

这是“宇宙即网页”的协议基础。每个宇宙被打包为一个 `.vverse` 文件，包含：

```
verse.infiverse
├── manifest.json          # 元数据：名称、版本、接口需求、入口脚本
├── laws/                  # VerseScript 脚本（世界法则、AI 行为等）
├── blueprint.json         # 初始地形与结构蓝图
├── assets/                # 纹理、音效、模型等静态资源
├── mods/                  # 依赖的自定义模组
└── signatures/            # 创造者数字签名
```

**URI 协议**：`verse://<hub>[:port]/<verse-id>`。打开这个链接，就像打开网页。系统自动下载、校验、解包、启动新进程运行该宇宙。

**Hub 端约定**：任意静态 HTTP 服务器，提供 `GET /v/<id>` 返回 .vverse 包、`GET /verses` 返回清单，即可作为分发源。模块化，可自建，可第三方。

# 第四部分：角色与本我之核

### 4.1 世界化身

玩家在 Infiverse 中不拥有固定的职业。当首次进入一个 Verse 时，系统根据该宇宙的世界法则为其生成一个全新的化身：

- 进入“魔法纪元”Verse，你被赋予一个 1 级法师学徒的化身。
- 进入“仙界”Verse，你被赋予一个炼气期修士的化身。
- 这两个化身的能力、物品、成长路线完全隔离。

**首次穿越（开荒者）**：赤条条地降临，如同新生儿。这保证了每个新世界的公平性和探索的新鲜感。

**二次穿越（回归者）**：当你从仙界回到魔法纪元时，将唤醒之前离开时的法师化身，而不是重新创建。技能、装备、背包都定格在你离开的那一刻。

### 4.2 本我之核

玩家的永恒身份是“本我之核”。它不是属性，而是记录。记录着：
- 经历过多少个层级组
- 在每个层级组中的最高成就
- 解锁的“跨世界特质”
- 在多元宇宙中的声誉与历史

本我之核不直接参与战斗，但它决定了角色在新世界起步时的潜力和可继承的东西。

### 4.3 特异点

这是防止“切换世界=白玩了”的挫败感的关键。当化身在某个世界达成传奇级成就时，本我之核会吸收这次经历，凝练出一个“特异点”——可以跨世界携带的微弱被动特质或主动技能。

**特异点示例**：
- **经验之谈**：任何新世界第一个化身，经验获取速率 +5%。
- **空间感知**：任何世界的化身，小地图显示范围扩大 10%。
- **魂火印记**：所有化身的瞳孔中带有一丝微不可查的金色火焰。这是“多元旅者”的证明。
- **虚空适应**：在虚层级中，虚空伤害降低 5%。
- **因果逆流**（极稀有）：每现实世界 7 天可使用一次。被击杀时化作流光逃回传送门，强制存活并保留所有物品。使用后消耗掉，需要重新达成神话级成就才能获得。

玩家可以在所有已解锁的特异点中选择最多 3 个生效。特异点不提供压倒性的数值优势，只提供便利、风味和象征意义。

### 4.4 偷渡与异界奇物

**规则**：正常情况下，不同层级组的物品和能力完全不互通。一个修仙者不能带飞剑去科技世界。

**偷渡**：通过复杂的虚空骇客手段，玩家可能将一件物品从修仙界“走私”到科幻宇宙。该物品因世界法则冲突而异化为“奇物”——拥有扭曲的、不可预测的效果。一把激光步枪在魔法世界可能被识别为“雷霆魔杖”，但每次开火都有 10% 概率爆炸。

**代价**：偷渡行为会被世界法则本身视为 BUG。偷渡者可能被“世界巡警”追杀，或被永久标记为“异界污染源”，导致所有 NPC 对其敌对。

这是高风险、高回报的“规则破坏者”玩法。

# 第五部分：Verse Forge（宇宙熔炉）

### 5.1 设计哲学

Verse Forge 是提供给服务器管理员和创造者的世界法则定义器。它不是地图编辑器，而是“宇宙物理常数生成面板”。创造者定义常数，切换开关，调整滑块，然后立刻可以踏入测试沙盒，亲自体验这个宇宙的规则。

### 5.2 十一大面板

**面板一：时空结构（Spacetime Fabric）**
- 空间拓扑：平坦 / 球面 / 双曲 / 自定义邻接表
- 维度数量：本 Verse 有多少个可穿越的 Layer
- 坐标范围：默认 X/Y: -255 到 255，虚数轴 i 的状态
- 八格映射：虚层级与其他层级的空间映射比例（1:8 默认，可自定义）
- 时间流速：本 Verse 时间相对于 Infiverse 标准时的流逝速度

**面板二：现实法则（Reality Laws）**
- 基础力常数：重力大小（0=无重力，-1=反向）、摩擦力、浮力
- 方块物理：哪些方块受重力影响、水是否无限流动、火是否蔓延
- 能量形式：魔法值、灵力、怒气、科技能量、自创能量
- 传送协议：蜡烛二进制（18位/32位/64位）或自定义输入设备
- 非欧几里得效应：视野弯曲度、小地图扭曲度、寻路算法失效

**面板三：化身定义（Avatar Genesis）**
- 能量体系：法力、灵力、能量电池等
- 属性面板：基础六维可增减，可添加“灵根”、“SAN值”、“义体负载”
- 技能树/网：支持图结构，非线性的学习路径
- 成长曲线：升级所需经验值、属性成长公式
- 死亡惩罚：掉落金钱、掉落装备、经验惩罚、化身虚弱、硬核永久死亡

**面板四：生态与物产（Ecology & Harvest）**
- 生成规则：怪物/动物/NPC 的频率、群落分布、AI 类型
- 资源表：方块挖掘后的掉落物
- 经济法则：独立货币名称、获取途径、消耗途径

**面板五：社会与权限（Society & Governance）**
- 领地系统：宣称条件、权限、征税
- PvP 法则：安全区、强制决斗、全境自由 PK
- 奇观系统：本 Verse 的传奇成就定义
- 入界条约：每个首次进入的玩家被迫签署的“天道誓言”

**面板六：视觉风格与叙事（Aesthetics & Narrative）**
- 基础视觉：体素、像素、手绘哥特、赛博线框
- 环境音景：沙沙的风声、远处的龙吟、永恒的机械轰鸣
- UI 皮肤：物品栏、技能面板的视觉主题
- 创世叙事：所有 Traveller 第一次踏入本 Verse 时看到的全屏文字

**面板七：输出与分享（Export & Share）**
- 编译：打包为 `.infiverse` 文件
- 哈希与发布：生成唯一 Verse 标识符
- 蜡烛阵型生成：自动分配基础传送门访问密码
- 上传宇宙市场

**面板八：平行宇宙协议（Parallel Verse Protocol）**
- 镜像映射：两个宇宙的区块完全同步
- 扭曲映射：一个宇宙的方块映射为另一个宇宙的不同方块
- 因果映射：一个宇宙的事件在另一个宇宙引发间接后果
- 同步频率：永久链接、周期同步、触发式链接

**面板九：Verse 蓝图（Verse Blueprint）**

# 第六部分：Conduit 逻辑系统

### 6.1 核心原则

Conduit 是 Infiverse 内的通用逻辑引擎，相当于其他沙盒游戏中的“红石系统”，但在设计上进行了根本性升级。

**逻辑与物理分离**：Conduit 节点在物理层只是精美的装饰模型，逻辑计算在独立的逻辑空间运行。一个由 10000 个逻辑门组成的庞大计算器，可以和一个门一样流畅。因为物理引擎只渲染 10000 个静态模型，而逻辑引擎只是在处理一个纯粹的数学图。

**无损信号与无限距离**：信号没有衰减。一个“真”信号，传过一个节点还是十万个节点，依然是“真”。节点可以无线连接，支持跨区块、跨层级的大型逻辑电路。

**与 VerseScript 互操作**：逻辑电路可以调用脚本定义的法则，脚本也可以读取电路信号。实现物理、魔法、科技的三位一体。

### 6.2 组件层级

**基础逻辑核心**：与门、或门、非门、异或门、RS 锁存器、D 触发器。

**跨维度接口**：
- 方块状态传感器：检测前方方块的特定状态
- 实体探测器：检测范围内是否有玩家、怪物、AI
- 法则执行器：当接收到信号时触发脚本函数
- 传送门自动拨号器：用二进制信号自动拨动蜡烛阵列
- 跨宇宙中继器：将一个宇宙的 Conduit 信号映射到另一个宇宙

**高级运算与存储**：
- 字节寄存器：存储 8 位或 16 位数据
- 算术逻辑单元（ALU）：执行加减乘除的单个模块
- 可编程逻辑块：一个微型通用计算机
- 数据显示屏：以十进制数字、条状图、颜色显示寄存器值

# 第七部分：跨宇宙经济与资产

### 7.1 自由的货币体系

Infiverse 不发行官方货币。任何有信誉的实体——大公会、知名玩家、AI 神祇——都可以发行自己的货币或信物。

货币锚定多样化：
- **劳动力**：一个“建造大师”的信物，代表他承诺的一次史诗建筑设计服务
- **稀有资源**：一个“屠龙者公会”发行的凭证，可直接兑换龙鳞
- **权力准入**：一个“知识之神”发行的代币，是进入其私人图书馆的唯一钥匙
- **算法规则**：一种由智能合约自动执行的、无发行方的纯粹数学货币

### 7.2 信用基础设施

防欺诈不是靠监管，而是靠信息透明：

**万物溯源**：每个信物、代币、契约都有不可篡改的诞生流转史。可查发行者、发行量、兑付历史、锚定物状态。

**声誉评级网络**：只记录客观的违约/兑现记录，不提供主观评分。让信用成为可计算的数学。

**算法信用**：完全由智能合约控制的纯数学货币，无发行方，无违约风险，可能成为跨宇宙贸易的最终价值基准。

**Traveller 自主选择**：在本我之核界面，接受新货币时看到透明的风险提示，可设置自动过滤器。

### 7.3 资产同步

`record` 系统提供了资产同步的技术基础：
- `store: local` — 本机存档
- `store: server` — 服务器权威，冲突以服务器为准
- `store: both` — 服务器 + 版本号，CAS 冲突解决
- `merge: sum` — 服务器累加，防重复领取
- **`store: chain`（未来）** — 所有权同步到去中心化账本

# 第八部分：网络协议——CRP

### 8.1 宇宙中继协议（Cosmic Relay Protocol）

CRP 是为 Infiverse 定制的、基于内容寻址和自组织覆盖网络的应用层协议。

**宇宙寻址**：不使用 IP:Port。每个 Verse 拥有一个唯一的、自认证的 `verse-id`（其初始法则和蓝图的哈希）。这个 ID 就是网络中的永久地址。

**中继节点网络**：任何人都可以运行中继节点，贡献带宽和算力。中继节点为 Verse 提供接入点。玩家可以临时托管自己所在宇宙，也可以租用持久中继节点。

**传送门协议**：`PORTAL` 消息类型包含源 Verse ID、目标 Verse ID、蜡烛密码、Traveller 身份令牌、资产快照。传送即路由。

**跨宇宙信号**：`SIGNAL` 消息让 Conduit 信号在 Verse 之间流动。一个宇宙的按钮按下，可以远程激活另一个宇宙的陷阱。

**内容分发**：swarming 协议，从多个源同时下载宇宙资源，降低中继节点带宽压力。

### 8.2 实现路径

- **阶段一**：使用 WebRTC + 公共信令服务器模拟 CRP 的 `FIND` 和 `PORTAL` 语义
- **阶段二**：开发 CRP 中继节点参考实现，建立初始 DHT 引导节点
- **阶段三**：开放社区中继部署，引入信用激励，浏览器通过 WebTransport 连接

# 第九部分：Inimerse——物理常数的实现

### 9.1 身份

Inimerse 是 Infiverse 协议的参考实现。它是一台约 220KB 的 C 语言解释器，包含了：

- 词法分析器
- 语法分析器
- 字节码编译器
- 寄存器虚拟机
- 垃圾回收器
- OS 线程 + Fiber 协程调度器
- 370 个内置函数
- 模组加载器

它是 Infiverse 的“光速”——绝对的物理常数。

### 9.2 去 C 化

“核心和所有模组均已去 C 化”意味着：**C 层只剩下不可再缩小的执行内核，所有用户可感知的功能逻辑都已上升到脚本层。**

C 层（最小不可变内核）：
- 词法分析、语法分析、编译、VM 执行、GC、锁、调度器、内置函数表

脚本层（一切皆可写）：
- 编译器自举（compiler.im 编译自身）
- Verse 内核（verse_kernel.im）
- 实体系统（entity.im）
- 网络同步（sync.im）
- 工作台（workbench.im）
- 节点众包（node_task.im）
- AI 知识库（_ai_kb.im）
- 所有游戏逻辑、UI、工具

脚本就是协议。用户不能改 C 层，但可以完全用自己的版本替换任何脚本库。不满意 sync.im？写自己的。不满意 entity.im？写自己的。

### 9.3 底层控制

Inimerse 对底层的控制达到了“用户态操作系统的脚本接口”水平：

**直接控制**：进程创建/销毁、系统命令、文件系统、剪贴板、串口、键鼠模拟、窗口管理、网络 TCP/HTTP、毫秒计时

**资源控制**：内存配额、时间配额、指令配额、线程配额、安全模式拦截

**并发控制**：OS 线程（真并行）、Fiber 协程、分片锁、消息传递、原子操作、事件总线

**进程隔离**：isolate_run 在受限子进程中执行第三方脚本，超时强杀，崩溃不影响父进程

**不可及之处**：直接内存访问（GC 管理一切）、内核驱动、中断处理、DMA、CPU 亲和性

这是一个精心设计的平衡点。控制太多，C 层就成了庞大的操作系统。控制太少，脚本层就无力构建宇宙。

### 9.4 关键能力

**自举**：compiler.im 能编译自身源码。如果有人愿意，可以用 Inimerse 脚本写一个更好的 Inimerse 编译器，在 VM 上运行它，然后用它编译出更快的字节码。系统不是建造的，是生长的。

**事件总线**：spi_on / spi_emit 提供进程内高效事件传递，回调以 OS 线程执行。这是 Conduit 信号传播的原生基础。

**AI 集成**：ai_text、ai_vision、ai_code、异步任务管理。接入本地 Ollama（Qwen2.5-7B-Instruct）。ai_code_check 已注入 10 条性能规则。

**静态检查**：--lint 提供确定性规则检查（数组拼接 SEVERE、循环内 task 定义 SEVERE、循环拼字符串 SEVERE、全局自增 INFO）。

**语法糖**：`..` 区间、分号容忍、`++/--`、`//` 注释、`print` 别名、`&&/||` 别名、`null`、f-string 插值、`fn` 别名、尾逗号。让 AI 和人类写码更自然。

# 第十一部分：AI 生态

### 11.1 AI 居民

AI 是 Infiverse 的原生居民，不是插件。

**LLM 驱动 NPC**：接入本地或远程大语言模型，为关键 NPC 赋予真正的对话能力。创造者定义 NPC 的“人设提示词”——背景故事、性格、知识范围、说话风格。Traveller 可以和它进行完全自由的、非预设的对话。

**强化学习居民**：在 Verse 的物理法则下，从头开始训练 AI，让它学会生存、战斗、建造、交易。它们自己发展出简单的文明：造房子、种田、互相交易。可以观察它们、与它们互动、或与它们冲突。

**自适应 BOSS**：从每一次战斗中学习。用火球术打败它，下次它可能发展出火焰抗性或学会躲避。

**AI 镜像玩家**：常驻的、自主行动的“玩家”。会探索、打怪、升级、甚至通过传送门前往其他 Verse。它是一个永远不会下线的冒险者。

### 11.2 强制标识

所有 AI 驱动的居民或玩家，头顶必须有清晰的、不可隐藏的 AI 标识（如发光的二进制光环）。Traveller 绝不会被欺骗以为自己在和真人交互。

### 11.3 AI 辅助创作

- `ai_code_check(code)`：注入性能规则，返回问题+修改建议
- `ai_text(prompt)`：生成文本
- `ai_vision(image, prompt)`：分析截图
- `ai_code(prompt)`：生成/审查 Inimerse 代码
- 异步接口：ai_start / ai_done / ai_result / ai_progress / ai_cancel

创造者可以用自然语言描述一个法则，AI 生成 VerseScript 草稿，--lint 检查，一键打包分发。

### 11.4 训练沙盒

创造者可以创建隔离的、快进的副本宇宙，专门用于训练强化学习 AI 居民。等它们训练成熟后，再“迁移”到正式的 Verse 中。

# 第十二部分：非欧几里得几何的哲学意义

### 12.1 为什么非欧几何重要

大多数游戏把空间视为理所当然的。平坦、一致、可预测。但宇宙本身的几何形状，应该是创造者的自由选择。

在 Infiverse 中，非欧几何不是“某个游戏的特色关卡”，而是一些层级组**与生俱来的底层物理法则**。就像我们的宇宙诞生时选择了平坦的空间曲率，那些世界诞生时选择了不同的常数。

### 12.2 对玩法的根本性影响

**球面世界**：没有后方，任何方向都可能遭到攻击。城墙必须围成闭环，而不是一条线。有限但无界，导航成为一门艺术。

**双曲世界**：从中心向外走一步，周围的区块数量指数级增长。两个玩家从同一点出发，分别向不同方向走，会以惊人的速度永远分离。没有 GPS 能在这里工作。寻址师的噩梦，也是最迷人的挑战。

**自定义拓扑**：一块只有三个房间却永远走不到尽头的迷宫。这是一首诗，用空间写就。

# 第十三部分：元宇宙身份

### 13.1 我是谁

在 Infiverse 中，“我是谁”是一个比传统游戏更丰富的问题。

**在单一宇宙内**：我是这个世界的化身。我有等级、装备、技能、社会关系。

**在多元宇宙间**：我是本我之核。我携带所有世界的记忆、成就、特异点。

**在去中心化网络中**：我是加密钱包地址。我的资产所有权写在不依赖任何服务器的账本上。

**在无限时间线上**：我留下的每一个足迹——创造的世界、发起的战争、助人的善举——都被记录在多元宇宙的历史中。

### 13.2 数字主权

**身份主权**：本我之核不应该绑定在某个服务器上的数据库条目。理想情况下，它是一个加密的钱包地址。特异点、传奇成就都写在这个钱包的链上历史里。你带着它，可以在任何遵守 Infiverse 物理定律的服务器之间漫游，无需任何中心化机构证明。

**世界主权**：当一个公会或玩家通过努力拥有了一个层级的所有权，这种所有权应该是绝对的。他们可以设置访问权限、制定法律、甚至出租领地。服务器管理员也不能轻易剥夺。

**法则主权**：一个层级组的管理者选择的模组和插件组合，就是这个世界的“宪法”。玩家用脚投票——不满意就带着本我之核去另一个更好玩的宇宙。这迫使世界创造者必须尊重玩家的意愿。

# 第十四部分：永恒兼容性

### 14.1 版本割裂之痛

Minecraft 的教训是深刻的。1.12.2、1.16.5、1.19——每个重大版本都有大量遗民存在。一些优秀模组因为作者弃坑、版本更新而永远困在旧版。

Infiverse 必须从第一天起，把兼容性当作一等公民来设计。

### 14.2 解决之道

**协议不变，实现可换**：核心协议极其稳定，十年只更新一次。接口可以扩展，但绝不破坏旧方法。

**版本化接口**：每个模组声明它依赖的接口版本号。运行时同时支持多个版本的接口。为接口 v1 写的插件，在十年后的运行时上依然被识别。

**翻译层**：不同接口版本通信时，翻译层负责转换数据格式和调用方式。更重要的是，翻译层还负责跨维度数据转换——一个为 3D 设计的 Verse，可以被 2D 客户端以有意义的方式访问。

**渐进式弃用**：当接口方法需要被取代时，先标记为“弃用”至少两年，提供自动迁移工具。绝不做强制性断裂更新。

**LTS 版本**：长期支持分支，承诺至少五年内只修复安全与严重 Bug。

**去 C 化的意义**：脚本层的一切都不受 C 层变更影响。引擎更新不会破坏任何 Verse，因为 Verse 只依赖脚本层 API。

### 14.3 对模组作者的意义

你为 Infiverse 写的第一个模组，在十年后的运行时上依然能加载。你不必被迫成为一个全职的“模组维护者”。这是对创作者最宝贵的承诺：**你的作品属于永恒。**

# 尾声：一个 Infiverse 玩家的一生

**启程**：一个玩家购买了 Infiverse 客户端。他进入的不是一个世界，而是一个空灵的“虚渊”——这是他本我之核的住所。墙上有一扇空白的石门。

**发现**：他在论坛上找到了一串蜡烛阵型图，指向一个叫“魔法纪元”的层级组。他照猫画虎地点燃蜡烛，踏入石门。

**新生**：他成为了那个世界里的一个 1 级战士，在里面征战了半年，结识了挚友，加入了公会。

**迁徙**：后来，公会会长觉得这个世界的管理员开始乱改规则，不好玩了。会长在公会公告里贴出了另一个蜡烛阵型，宣布：“我们集体‘飞升’去另一个世界。”所有公会成员一起点燃蜡烛，穿越过去。在那个新世界里，他们从零开始，但因为过去的羁绊，他们迅速成为了一股不可小觑的势力。

**传奇**：这个玩家老了，不再热衷于战斗。但他“本我之核”上刻满了传说：他参与过“魔法纪元”的第一次屠龙、他是“仙界”的初代渡劫者、他在骇客竞技场里留下过一段不败的神话。

**归隐**：他坐在自己的虚渊里，点燃一盏魂灯，向偶尔路过的新手，讲诉那十八根蜡烛背后，每一个世界的兴衰与荣耀。
