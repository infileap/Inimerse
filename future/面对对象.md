# Eidos 面向对象系统完整规范 v2.0

## 一、Eidos 概述

Eidos（希腊语：εἶδος，意为“形态/本质”）是 Infiverse 的面向对象系统。它为多宇宙、多法则、多形态而设计，融合多种语言的优点，并引入宇宙变换、热修改等独有特性。

**核心思想**：对象不是固定属于某个类，而是“存在的一种形态”。对象可以穿越不同宇宙，自动变换形态，同时保留其本质身份。

## 二、基础语法

### 2.1 Eidos 定义

```python
eidos Monster {
    # 属性（自动成为构造参数）
    name = "Monster"
    hp = 100
    attack = 10
    _temp = 0        # 下划线前缀表示私有

    # 无参数方法：省略 ()
    die {
        say name + " 死了"
    }

    # 有参数方法：保留 ()
    take_damage(n) {
        hp -= n
        die if hp <= 0
    }

    # 单行方法：-> 自动返回
    is_alive -> hp > 0
}
```

**关键规则**：
- 属性声明即构造参数，按声明顺序，支持命名参数和默认值
- 方法内直接使用属性名，无需 `this.` 或 `.`
- **无参数方法定义时可省略 `()`**，调用时同样可省略
- 单行方法可用 `->` 自动返回
- 下划线 `_` 前缀表示私有属性/方法

### 2.2 方法调用形式

```python
m = Monster("龙", 500)

# 无参数方法：两种调用方式等价
m.die
m.die()

# 有参数方法：必须带括号
m.take_damage(30)
```

### 2.3 实例化

```python
m1 = Monster()                      # 全默认
m2 = Monster("龙", 500, 20)          # 位置参数
m3 = Monster(hp = 300)               # 命名参数
m4 = Monster("Boss", attack = 80)    # 混合参数
```

无需 `new`，属性自动生成 getter/setter。

### 2.4 构造函数

只有需要额外初始化逻辑时才写 `init`：

```python
eidos Boss: Monster {
    phase = 1
    is_enraged = false

    init {
        if hp < 500 {
            is_enraged = true
            say name + " 进入狂暴！"
        }
    }
}
```

`init` 在所有属性赋值完成后自动调用。无参数时省略 `()`。

### 2.5 继承

```python
eidos Boss: Monster {         # 单继承
    phase = 1

    take_damage(n) {
        n = n / 2 if phase == 2
        super.take_damage(n)   # 调用父类方法
    }
}

eidos Flying {
    flying = true
    fly { say name + " 飞了起来" }
}

eidos Dragon: Monster + Flying {   # 多重继承（Mixin）
    # 同时继承 Monster 和 Flying
}
```

**规则**：
- 单继承用 `:`，多重继承（Mixin）用 `+`
- 方法查找从左到右，子类优先
- `super` 调用最近的父类实现

### 2.6 运算符重载

```python
eidos Vector {
    x = 0
    y = 0

    +(v) -> Vector(x + v.x, y + v.y)
    -(v) -> Vector(x - v.x, y - v.y)
    *(s) -> Vector(x * s, y * s)
    ==(v) -> x == v.x and y == v.y
}

v1 = Vector(1, 2)
v2 = Vector(3, 4)
v3 = v1 + v2       # → Vector(4, 6)
```

### 2.7 自定义 getter/setter

```python
eidos Player {
    _hp = 100

    get hp -> _hp
    set hp(v) {
        _hp = max(0, v)    # 血量不能为负
    }
}
```

无参数 getter 省略 `()`。

### 2.8 匿名对象

```python
npc = {
    name = "临时NPC"
    hp = 50
    talk { say name + " 打招呼" }
}
```

## 三、on 关键字：上下文与事件绑定

### 3.1 on 的三种用途

`on` 是 Infiverse 的**上下文绑定运算符**，它有三种形式：

| 形式 | 语法 | 作用 |
|---|---|---|
| **对象线程绑定** | `on obj { ... }` | 启动线程，自动绑定 `obj` |
| **事件订阅** | `on "event" { ... }` | 注册事件处理器 |
| **生命周期钩子** | `on_update { ... }` | 定义对象生命周期回调 |

### 3.2 对象线程绑定

```python
# 形式一：绑定已有实例
m = Monster("龙", 500)
on m {
    # 此代码块运行在独立线程，this 自动绑定 m
    # 属性直接访问，无需 m.hp
    while true {
        take_damage(1)    # 相当于 m.take_damage(1)
        wait 0.1
    }
}

# 形式二：绑定精灵名字（Scratch DSL 兼容）
on Cat {
    # 自动绑定名为 "Cat" 的精灵
    move 5
}
```

### 3.3 事件订阅

```python
# 订阅游戏内广播事件
on "level_up" {
    say "升级了！"
    play_sound("levelup.wav")
}

# 订阅自定义事件
on "player_death" {
    respawn_player()
    show_game_over()
}

# 事件携带数据
on "item_pickup" {
    item = event_data()          # 获取事件数据
    say "拾取了 " + item.name
}
```

### 3.4 生命周期钩子

在 Eidos 定义内部，`on_` 前缀方法自动成为生命周期钩子：

```python
eidos PlayerSprite: Sprite {
    hp = 100

    # 生命周期钩子（自动调用）
    on_spawn {
        say name + " 出现了"
        play_animation("appear")
    }

    on_update {
        if key("left")  { move(-speed) }
        if key("right") { move(speed) }
    }

    on_collision(other) {
        if other.touches(self) {
            take_damage(10)
        }
    }

    on_click {
        say "你点击了 " + name
    }

    on_destroy {
        say name + " 被销毁"
        emit("entity_destroyed", this)
    }
}
```

### 3.5 完整生命周期

| 钩子 | 触发时机 | 参数 |
|---|---|---|
| `on_spawn` | 对象创建完成 | 无 |
| `on_update` | 每帧更新 | 无 |
| `on_collision` | 与其他对象碰撞 | `other` |
| `on_click` | 被点击 | 无 |
| `on_edge` | 触碰边界 | 无 |
| `on_destroy` | 被销毁前 | 无 |
| `on_enter_verse` | 穿越进入新宇宙 | `verse_id` |
| `on_leave_verse` | 离开当前宇宙 | `verse_id` |
| `on_violation` | 不变量被违反 | 无 |

### 3.6 on 与线程的关系

```python
# 显式启动线程并绑定
on player {
    # 独立线程，this = player
    while true {
        on_update
        wait 0.016
    }
}

# 等价于
thread player_thread {
    bind(player)
    while true {
        on_update
        wait 0.016
    }
}
```

## 四、开放与封闭

Eidos 采用**渐进式封闭**：默认全开放，按需封闭。

### 4.1 可见性

| 访问级别 | 表示 | 说明 |
|---|---|---|
| 公有 | `name` | 默认，外部可读写 |
| 私有 | `_name` | 约定私有，运行时警告（可选 `--strict-visibility` 编译错误） |

### 4.2 final 方法与类

```python
eidos Monster {
    final die { ... }           # 子类不能重写
}

final eidos Boss: Monster { ... }  # 不能被继承
```

### 4.3 sealed 类

```python
sealed eidos Shape {
    # 只允许同文件内的子类
}

eidos Circle: Shape { ... }
eidos Square: Shape { ... }
# 其他文件中的 eidos Triangle: Shape 会编译错误
```

### 4.4 frozen 属性

```python
eidos ImmutablePoint {
    frozen x = 0
    frozen y = 0
}

p = ImmutablePoint(5, 3)
# p.x = 10   # 编译错误：frozen 属性不可修改
```

### 4.5 不变量约束

```python
eidos Player {
    level = 1
    exp = 0

    invariant {
        level >= 1
        exp >= 0
        exp < level * 100
    }

    on_violation {
        if exp >= level * 100 {
            level += 1
            exp = 0
            emit("level_up", this)
        }
    }
}
```

每次属性修改后自动检查不变量，违反时触发 `on_violation`。

## 五、Infiverse 特色特性

### 5.1 热修改

Eidos 可被重新定义，所有现有实例立即生效：

```python
eidos Monster {
    hp = 100
    speed = 5
    ai_loop {
        while true {
            move(speed)
            wait 0.03
        }
    }
}

monsters = []
for i in range(10) { push(monsters, Monster()) }

# 热修改：提速并添加新行为
eidos Monster {
    hp = 100
    speed = 10
    ai_loop {
        while true {
            move(speed)
            if hp < 50 { move_away(speed * 2) }  # 新增逃跑行为
            wait 0.03
        }
    }
}
# 所有现有怪物立即获得新速度和逃跑行为
```

**安全网**：修改失败自动回滚，游戏继续。

### 5.2 宇宙变换

对象穿越宇宙时自动变换形态：

```python
eidos MagicalSword {
    damage = 50
    element = "fire"

    strike -> damage
}

eidos CyberBlade {
    damage = 80
    energy_cell = 100

    strike {
        energy_cell -= 1
        return damage
    }
}

verse_mapping MagicalSword -> CyberBlade when "magic" -> "cyberpunk" {
    damage -> damage
    element -> nil
    nil -> energy_cell
}

sword = MagicalSword()
say sword.element          # "fire"
enter_verse("cyberpunk")
say sword.element          # nil（属性消失）
say sword.energy_cell      # 100（新属性出现）
say sword.strike()         # 80（使用新形态的方法）
```

### 5.3 多元化 say

`say` 根据执行上下文自动路由，也可显式指定目标：

```python
on Player {
    say "我准备好了"              # 自动 → 精灵头顶气泡
    say "准备完成" to "hud"       # 显式 → HUD
    say "玩家已准备" to "log"     # 显式 → 日志
}
```

目标包括：`console`、`bubble`、`hud`、`log`、`broadcast`、`file:path`、`ai`、`network`。

## 六、Sprite 的 Eidos 化重构

### 6.1 Sprite 基类

```python
eidos Sprite {
    name = "Sprite"
    image_path = ""
    x = 0.0
    y = 0.0
    direction = 0.0
    size_pct = 100
    vx = 0.0
    vy = 0.0
    gravity = 0.0
    visible = true
    collision_box = nil

    init {
        if image_path != "" { _native_create }
    }

    _native_create {
        gui_sprite(name, image_path)
        gui_goto(x, y, name)
        gui_size(name, size_pct)
        if visible { gui_show(name) } else { gui_hide(name) }
    }

    move(steps) {
        gui_move(steps, name)
        x = x(name)
        y = y(name)
        return this
    }

    goto(nx, ny) {
        x = nx
        y = ny
        gui_goto(nx, ny, name)
        return this
    }

    face(dir) {
        direction = dir
        gui_face(name, dir)
        return this
    }

    turn(delta) {
        direction += delta
        gui_turn(name, delta)
        return this
    }

    resize(pct) {
        size_pct = pct
        gui_size(name, pct)
        return this
    }

    set_velocity(nvx, nvy) {
        vx = nvx
        vy = nvy
        gui_velocity(name, nvx, nvy)
        return this
    }

    set_gravity(g) {
        gravity = g
        gui_gravity(name, g)
        return this
    }

    show { visible = true; gui_show(name); return this }
    hide { visible = false; gui_hide(name); return this }

    set_collision_box(bx, by, bw, bh) {
        collision_box = [bx, by, bw, bh]
        gui_box(bx, by, bw, bh, name)
        return this
    }

    clone {
        new_name = name + "#" + str(rand(1000, 9999))
        gui_clone(name)
        return new Sprite(new_name, image_path, x, y)
    }

    delete { gui_delete(name) }
    touches(other) -> touch(other.name)

    # 生命周期钩子
    on_update { }
    on_collision(other) { }
    on_click { }
    on_edge { }
}
```

### 6.2 继承与多态

```python
eidos PlayerSprite: Sprite {
    hp = 100
    speed = 6

    init {
        super.init
        set_collision_box(10, 10, 30, 30)
    }

    on_update {
        if key("left")  { move(-speed) }
        if key("right") { move(speed) }
    }
}
```

### 6.3 DSL 兼容

旧的 `on SpriteName { ... }` 语法仍然有效，内部自动创建 Sprite 实例并绑定线程。

## 七、虚函数调用优化

Eidos 方法分派从字典查找逐步优化到接近原生性能。

### 7.1 分派优化层次

| 层次 | 方法 | 相对原始提速 |
|---|---|---|
| L0 字典查找（当前） | 按字符串哈希 | 1x |
| L1 vtable 索引 | 编译期确定方法索引，运行时数组访问 | 10x |
| L2 内联缓存 | 调用点缓存上次类型-方法对 | 25x |
| L3 多态内联缓存 | 缓存 2-4 种类型 | 接近 vtable |
| L4 去虚拟化 | sealed/final/局部类型确定 | 直接调用 |
| L5 JIT 内联 | 热点方法内联 + 优化 | 100-500x |

### 7.2 与 Eidos 特性的协同

| 特性 | 优化作用 |
|---|---|
| `sealed` | 允许编译期去虚拟化 |
| `final` | 安全内联 |
| 单行方法 `->` | 天然适合内联 |
| 无参数方法省略 `()` | 减少语法噪音，利于编译优化 |
| 热修改 | 版本号失效缓存 |
| 宇宙变换 | 类型检查确保安全 |

### 7.3 实现计划

1. vtable 化（1-2 周）
2. 内联缓存（1 周）
3. sealed/final 优化（1 周）
4. JIT 内联（与整体 JIT 合并，3-12 周）

## 九、完整示例

```python
# 定义一个游戏实体
eidos Player: Entity {
    name = "玩家"
    hp = 100
    max_hp = 100
    level = 1
    exp = 0
    position = Vector(0, 0)

    invariant {
        hp >= 0
        level >= 1
    }

    take_damage(n) {
        hp -= n
        die if hp <= 0
    }

    heal(n) {
        hp = min(hp + n, max_hp)
    }

    level_up {
        level += 1
        max_hp += 50
        hp = max_hp
        emit("level_up", this)
    }

    _die {
        say name + " 死了" to "broadcast"
    }

    +(other) -> Player(name, hp + other.hp)

    # 生命周期钩子
    on_spawn {
        say name + " 加入了游戏"
    }

    on_update {
        position = position + velocity * dt
    }

    on_destroy {
        say name + " 离开了游戏"
    }
}

# 使用
p1 = Player("战士", 200, 200)
p2 = Player("法师", 150, 150)

p1.take_damage(30)
p1.heal(10)
p1.level_up

# 线程绑定
on p1 {
    while true {
        take_damage(1)
        wait 0.1
    }
}

# 事件订阅
on "player_level_up" {
    say "有玩家升级了！"
}
```

## 十、设计总结

| 原则 | 实现 |
|---|---|
| 声明即构造 | 属性自动成为构造参数 |
| 直接属性访问 | 方法内 `hp` 而非 `this.hp` |
| 省略可推导 | 类型、返回类型、可见性、无参数方法的 `()` 全部省略 |
| 约定优于配置 | `_` 前缀表示私有 |
| 单行优化 | `->` 自动返回 |
| 渐进式封闭 | 默认开放，按需使用 final/sealed/frozen |
| 宇宙意识 | 热修改、宇宙变换、不变量 |
| 上下文绑定 | `on` 统一处理线程绑定、事件订阅、生命周期钩子 |
| AI 友好 | 注释规范、API 元数据、多元化输出 |
| 高性能 | vtable + 内联缓存 + JIT 去虚拟化 |

**Eidos 让定义宇宙中的存在像呼吸一样自然，`on` 让对象与线程、事件、生命周期的绑定变得直观，而省略无参数方法的 `()` 则进一步消除了语法的冗余。**
